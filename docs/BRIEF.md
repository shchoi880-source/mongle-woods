# 프로젝트 브리프 (모든 팀 필독)

## 무엇을 만드나
귀여운 2D **라이프 시뮬레이션 / 코지 게임**. 작은 마을(섬이 아니어도 됨)에 이사 와서 채집·낚시·곤충잡기·화석 발굴·가구 수집·집 꾸미기·주민과의 교류를 하며 **실제 시계**에 맞춰 천천히 살아가는 게임.
장르 레퍼런스는 동물의 숲·스타듀밸리 같은 "슬로우 라이프"지만, **완전한 오리지널**이어야 한다.
- 금지: 동물의 숲의 이름·캐릭터(너굴/여울/부엉/K.K. 등)·화폐명(벨/마일)·고유 시스템 이름(무 주식, 너굴포트, 마일리지 등)·아트를 흉내 내는 것. 장르 공통 메커닉(채집, 도감, 주민, 대출로 집 확장 등)은 OK, 이름·연출·세부 규칙은 우리 것으로.

## 사용자(오너)의 요구
- **고퀄리티**. 3D일 필요 없음. 2D로 "손맛·분위기·디테일"이 상위권 코지게임급.
- **귀여움**이 핵심 정체성.
- **매일 접속해도 최소 6개월 동안 할 게 남아야 함.** 단순한 게임은 아무도 안 한다.
- 지금 목표: 내부 회의 → **1차 베타(플레이 가능한 프로토타입)**. 이후 단계별 확장.

## 기술 제약 (고정)
- 순수 JavaScript + Canvas 2D, 빌드 도구·프레임워크 없음. 각 파일은 IIFE, 전역은 `window.G` 하나.
- GitHub Pages(정적 호스팅)로 배포. 서버 없음. 상대 경로만.
- 저장: 기기의 `localStorage`에만(용량 ~5MB 이내). 저장 데이터 버전 관리 + 마이그레이션 필수, 세이브 파일 내보내기/가져오기.
- PWA(서비스 워커)로 오프라인 실행. 폰(터치)과 PC(키보드/마우스) 모두 지원.
- 외부 이미지 에셋 없이 **코드로 그리는 그래픽**이 기본(오프스크린 캔버스에 미리 그려 캐시하는 방식 가능). 사운드는 WebAudio 절차적 생성.
- 모바일 성능 중요: 중저가 폰에서 60fps 목표.
- UI 언어: 한국어.

## 팀 구성 (각 팀 2인 페어: 구현 + 검토)
기획 / 월드·맵 / 시스템·경제 / 시간·생태 / 주민 AI / 대화·시나리오 / 하우징·꾸미기 / 아트A(캐릭터·생물) / 아트B(환경·가구) / 사운드 / UI·QA
총괄(Claude 메인)이 설계서(SPEC)·통합·배포를 맡는다.

## 회의 규칙
- 1차 회의: 각 팀이 자기 분야 제안서를 낸다. 두 멤버가 서로 다른 관점에서 의견을 내고 반론을 거쳐 합의안을 쓴다(의견 충돌은 기록).
- 제안은 **구체적**이어야 한다: 숫자, 목록, 데이터 구조, 규칙. "재밌게 한다" 같은 말 금지.
- 각 제안서는 반드시 **(1) 베타에 들어갈 것 (2) 6개월 로드맵에 들어갈 것**을 분리해서 쓴다. 베타는 2~3주 분량이 아니라 "지금 한 번에 만들 수 있는 최대 핵심"이다.
