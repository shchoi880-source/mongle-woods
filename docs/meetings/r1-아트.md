# 1차 회의 제안서 — 아트A(캐릭터·생물) + 아트B(환경·가구) 합동

- 참석: 아트A 하린(구현) · 도윤(검토) / 아트B 서진(구현) · 민규(검토)
- 전제: 이미지 파일 0개. 모든 그래픽은 Canvas 2D 코드로 그리고, 오프스크린 캔버스에 미리 그려 캐시한다. 중저가 폰 60fps.
- 원칙: 동물의 숲 실루엣·색감·캐릭터 비례를 그대로 흉내 내지 않는다. 우리 정체성 키워드 = **"말랑한 스티커 + 수채 그림자"**.

## 0. 쟁점 요약 (의견 충돌 기록)

| # | 쟁점 | 의견 A | 의견 B | 합의 |
|---|---|---|---|---|
| 1 | 스타일 | 하린: 둥근 벡터(path/arc) — 귀여움·확대 내성 | 민규: 픽셀아트 — 코드로 그리기 쉽고 성능·일관성 보장 | **둥근 벡터 + 굵은 아웃라인**, 단 "논리 해상도 정수 배율 캐시"로 픽셀아트의 선명함만 차용 |
| 2 | 시점 | 서진: 3/4 뷰(높이 있음, 절벽 2단) | 도윤: 순수 탑다운(충돌·정렬 단순) | **3/4 뷰(탑다운 그리드 + 세로 높이 표현)**. 충돌은 그리드, 그림만 높이 오프셋 |
| 3 | 캐시 vs 실시간 | 하린: 캐릭터는 매 프레임 path로 그려야 표정·스쿼시가 산다 | 민규: path 실시간은 폰에서 주민 10명이면 끝 | **부위별 캐시 + 실시간 합성**(머리/몸/귀/눈을 캐시 조각으로, 변형은 transform만) |
| 4 | 시간대 조명 | 서진: 팔레트 자체를 시간대별로 재생성 | 도윤: 재생성은 캐시 4배, 오버레이 한 장으로 충분 | **오버레이(multiply 1장 + 밤 조명 additive 1장)**. 팔레트 재생성은 계절만 |

| 6 | 가구 400종 | 서진: 생성기로 400+ 자동 | 도윤: 자동 조합은 "다 비슷해 보임" 위험 | **손으로 짠 기본형 60개 × 재질 × 색** + 기본형마다 전용 디테일 함수 1개 필수 |

## 1. 비주얼 스타일 · 카메라 · 해상도

### 1.1 토론
- **민규(픽셀아트 지지)**: "코드로 그린 벡터는 '플래시 게임'처럼 싸 보이기 쉽다. 픽셀아트는 16px 격자가 퀄리티를 강제한다."
- **하린(반론)**: "픽셀아트를 코드로 그리면 결국 fillRect 도트 노가다고, 귀여움의 핵심인 '둥근 볼·반짝이는 눈'이 계단이 된다. 고DPR 폰에서 벡터가 훨씬 고급스럽다."
- **도윤(검토)**: "벡터가 싸 보이는 원인은 ①얇은 아웃라인 ②단색 채움 ③기계적으로 완벽한 원이다. 이 셋을 규칙으로 막으면 된다."
- **합의**: 둥근 벡터. 싸 보임 방지 3규칙을 **아트 헌법**으로 고정:
  1. 모든 오브젝트는 **진한 동계열 아웃라인**(검정 금지, 채움색 명도 −45%, 채도 +10%) 두께 = 논리 1.5px(캐릭터 2px).
  2. 모든 면은 **3톤**: 베이스 / 그림자(좌하단, 명도 −15% 색상 +8° 보라 쪽) / 하이라이트(우상단 작은 타원, 명도 +20%, α0.6).
  3. 모든 곡선은 **워블**: 시드 고정 노이즈로 제어점 ±0.4px 흔들림 → 손으로 그린 맛. 시드는 캐시 키에 포함(매 프레임 흔들리지 않음).

### 1.2 카메라
- 3/4 뷰: 바닥 타일은 정사각 그리드, 오브젝트는 "정면+윗면" 동시에 보임. 높이 1단 = 논리 **12px** 위로 오프셋, 절벽 옆면 12px 노출.
- 카메라는 플레이어 추적, 데드존 24×16px, lerp 0.12/frame. 줌 고정(베타), 집 안은 1.25배.

### 1.3 해상도·DPR
- **타일 = 논리 32px**. 화면 기준 가로 최소 11타일 보이도록 `scale = floor_half(viewportCssW / (11*32))`(0.5 단위 스냅, 최소 1).
- 실제 픽셀 배율 `PX = scale * min(devicePixelRatio, 2)` — DPR 3 폰도 2로 캡(필레이트 절약, 체감 차이 미미).
- 메인 캔버스 크기 = CSS 크기 × min(DPR,2). `ctx.setTransform(PX,0,0,PX,0,0)` 후 논리 좌표로 그림.
- **흐림 방지**: ①캐시 스프라이트는 반드시 `PX` 배율로 렌더(키에 PX 포함) ②drawImage 위치는 `Math.round(x*PX)/PX` 스냅 ③`imageSmoothingEnabled=true`(벡터라 계단보다 약간의 AA가 낫다) 단 스케일 1:1 그리기만 허용.
- **들쭉날쭉 방지**: 아웃라인을 채움 *뒤*가 아닌 "외곽 확장 채움"(같은 path를 lineWidth×2로 stroke → 위에 fill)으로 처리 — 안쪽 경계에 AA 틈이 안 생김.
- DPR/화면 크기 변경 시 캐시 전부 무효화 후 지연 재생성(프레임당 최대 6ms 예산).

## 2. 렌더링 기술

### 2.1 스프라이트 캐시
- `G.art.cache`: `Map<key, {cv, ox, oy, w, h, lastUsed}>`. 키 형식 `"<kind>:<id>:<variant>:<season>:<PX>"` 예: `tree:oak:fruit2:autumn:2`.
- 생성: `new OffscreenCanvas` 지원 시 사용, 아니면 `document.createElement('canvas')`.
- 예산: 총 픽셀 **24M px(≈96MB RGBA) 상한**, 초과 시 LRU 제거. 중저가 폰 실측 후 16M로 하향 가능(민규 요청).
- 아틀라스: 타일류(바닥 64종)는 2048×2048 한 장 아틀라스로 묶어 drawImage 소스 전환 최소화.
- **청크 프리렌더**: 바닥 타일은 16×16타일 청크 단위로 한 장(512×512 논리)으로 굽고, 물 반짝임만 위에 덧그림. 청크 캔버스는 화면 근처 9개만 유지.

### 2.2 그리기 순서 (레이어)
1. 바닥 청크(캐시) → 2. 물 애니(실시간, 저비용) → 3. 그림자 레이어 → 4. **y-정렬 오브젝트**(나무·가구·캐릭터·바위; 정렬키 = 발밑 y + 높이단×0.01) → 5. 상단 전경(나뭇잎 캐노피 반투명) → 6. 날씨 파티클 → 7. 시간대 오버레이 → 8. UI(별도 DOM/캔버스).
- y-정렬은 화면 내 오브젝트만, 삽입 정렬(이전 프레임 순서 재활용 → 거의 O(n)).

### 2.3 그림자 (shadowBlur 금지)
- `shadowBlur`는 **런타임 사용 금지**(린트 규칙). 캐시 생성 시에만 허용.
- 바닥 그림자 = 미리 구운 **방사형 그라디언트 타원 1장**(64×32, 흑→투명, 색 #2a2340 α0.28)을 크기만 바꿔 drawImage. 점프·들기 시 y높이에 따라 scale 0.7~1.0, α 감소.
- 큰 오브젝트(나무·건물)는 그림자 모양을 캐시에 포함(나무 = 타원 2개 합성 후 블러 1회).

### 2.4 손맛 연출 (캐릭터·생물)
- **아이들 바운스**: 1.6초 주기 sin, 몸 scaleY 1.0↔1.03, scaleX 반대 0.985 (부피 보존).
- **걷기 스쿼시**: 발 디딤 순간 scaleY 0.94/scaleX 1.05, 80ms 복귀(easeOutBack).
- **눈 깜빡임**: 2.5~5.5초 랜덤, 감기 3프레임(60ms), 15% 확률 더블 깜빡.
- **귀 털기(ear flick)**: 6~12초 랜덤, 한쪽 귀 회전 −15°→0° 150ms 스프링.
- **꼬리**: 2차 스프링(k=60, damp=8)로 이동 방향 반대로 지연.
- **머리 기울이기**: 대화 시작 시 ±6°, 감정 아이콘 팝 scale 0→1.2→1.0.
- **림 라이트**: 해 질 녘·밤엔 캐릭터 실루엣 우측에 1px 밝은 테두리(캐시된 림 마스크를 `source-atop`으로 시간대 색 채움). 부위 캐시와 함께 1회 생성.

## 4. 캐릭터 디자인

### 4.1 플레이어 아바타
- 비율 **머리:몸 = 1 : 0.9 (약 2등신)**. 전체 높이 논리 40px(타일 1.25), 머리 지름 22px, 몸 16×14, 팔다리는 짧은 캡슐(손·발은 원 하나).
- 동숲식 "큰 머리 + 막대 다리"를 피하기 위해 **몸통이 물방울형(아래가 넓음)**, 다리 거의 안 보이는 '발 두 개' 스타일 — 우리 실루엣 차별점.
- 커스텀 파츠 (베타 수량 / 6개월 목표):
  - 피부톤 8 / 12
  - 헤어스타일 10 / 30 (앞머리·뒷머리 레이어 분리 → 모자와 조합 가능)
  - 헤어색 12 / 20
  - 눈 모양 8 / 20 (점눈, 반달눈, 반짝눈, 졸린눈 …) + 눈색 8
  - 볼터치 on/off + 색 4
  - 상의 형태 6 / 40, 하의 4 / 25, 신발 3 / 15, 모자 4 / 40 — 의상 색은 팔레트 24색에서 자유 지정
- 방향: 4방향(상하좌우), 좌=우 반전. 대각 이동은 가까운 축 방향 표시.
- 애니메이션 프레임(키포즈 수, 사이는 트윈 보간):
  | 동작 | 프레임 | 주기 |
  |---|---|---|
  | idle | 2 키(+바운스 트윈) | 1.6s |
  | walk | 4 | 0.48s |
  | run | 6 (몸 앞기울기 8°, 먼지 파티클) | 0.36s |
  | 도구 휘두르기(도끼/삽) | 5 (예비동작·타격·여운) | 0.5s |
  | 낚싯대 던지기/당기기 | 4 + 3 | — |
  | 잠자리채 휘두르기 | 4 | 0.35s |
  | 줍기/기쁨(아이템 들어올리기) | 3 + 홀드 | 1.2s |
  | 앉기·눕기(로드맵) | 2 | — |
- 구현: "인형 관절" 방식. 부위 = 머리·앞머리·뒷머리·몸·팔L/R·발L/R·눈·입. 각 부위를 PX별 캐시, 프레임은 부위별 (dx,dy,rot,sx,sy) 테이블. 아바타 1명당 캐시 ≈ 부위 11 × 방향 3 = 33장, 각 ≤48×48.

### 4.2 주민 동물 (베타 10종, 로드맵 20종)
- 베타 종: 토끼, 고양이, 강아지, 곰, 다람쥐, 오리, 양, 여우, 판다, 햄스터.
- 로드맵 추가: 펭귄, 사슴, 수달, 고슴도치, 코알라, 개구리, 부엉이 아닌 '참새', 너구리 아닌 '오소리', 알파카, 레서판다. (기존 유명 캐릭터 연상 종은 디자인 시 색·무늬로 거리 둠)
- **파라메트릭 동물 바디 생성기** `G.art.animal.build(params)` — 한 주민 = 하나의 params JSON(약 30필드, 세이브에 id만 저장):
  ```js
  { species:'rabbit', seed: 1937,
    head:{ w:24, h:21, squish:0.92 },            // 머리 타원
    body:{ shape:'pear'|'bean'|'round', w:18, h:15 },
    ears:{ type:'long'|'round'|'tri'|'floppy'|'none', len:14, spread:0.35, innerColor:'#F7C6D0' },
    snout:{ type:'none'|'button'|'muzzle'|'beak', size:5, color:'#FFF3E6' },
    nose:{ shape:'tri'|'oval'|'heart', color:'#5A3A44' },
    eyes:{ style:'dot'|'gem'|'sleepy'|'lash', gap:9, size:3.2, color:'#2B2234' },
    tail:{ type:'puff'|'long'|'curl'|'fan'|'stub', len:8 },
    pattern:{ type:'none'|'belly'|'mask'|'spots'|'stripes'|'socks'|'patch', color:'#FFFFFF', seed:44 },
    fur:{ base:'#F2E6D8', shade:'#D8C2AE' }, cheek:'#FFB3B8',
    outfit:{ top:'tee', color:'#7FB8E6' } }
  ```
  - 종별 프리셋이 기본값과 허용 범위를 정의 → 같은 토끼도 귀 길이·무늬·털색·눈으로 개체 구분. 10종 × 평균 8개체 = 베타 주민 풀 80명 자동 생성 + 수제 튜닝.
  - **도윤 검토 조건**: 실루엣 테스트(검정 채움만으로 종 구분 가능해야 함) 통과 못 하면 프리셋 반려. 귀·꼬리·코 3요소 중 2개 이상 종마다 고유.
  - 하린 vs 도윤 쟁점: 하린은 "랜덤 개체 무한 생성"을 원했고, 도윤은 "랜덤은 못생긴 조합이 나온다"고 반대. → **수제 큐레이션 주민만 등장**(생성기는 제작 도구, 결과 params를 data에 고정).
- 주민 애니: idle/walk(4)/talk(입 2프레임)/감정 8종(기쁨·놀람·화남·슬픔·졸림·하트·생각·음표) — 감정은 얼굴 파츠 교체 + 머리 위 아이콘.

## 5. 생물: 곤충 60 · 물고기 60

### 5.1 곤충 생성기 `G.art.bug.build(p)`
- 몸 구조 템플릿 8개: 나비, 나방, 딱정벌레, 잠자리, 매미, 메뚜기, 개미/벌, 기타(달팽이·거미·무당벌레형).
- 파라미터: 템플릿, 몸 길이(6~18px), 몸 색 2, 무늬(점·줄·눈알무늬·그라디언트), 날개 모양 4종·색 2·투명도, 더듬이(곧은/곤봉/깃털), 광택(딱정벌레 하이라이트 강도).
- 월드 표시는 작게(8~14px) + 날갯짓 2프레임 캐시. 도감/획득 연출에서만 큰 사이즈(64px) 고퀄 버전 별도 캐시(외곽 디테일·광택 추가).
- 60종 = 8템플릿 × 평균 7.5 변주. 같은 템플릿은 **색+무늬+크기** 3축 중 2축 이상 다르게(검토 규칙).

### 5.2 물고기 생성기 `G.art.fish.build(p)`
- 월드에서는 **그림자만** 보인다(장르 공통 + 성능). 그림자 크기 6단계: XS(10×5) / S(14×7) / M(18×9) / L(24×12) / XL(32×16) / 지느러미(등지느러미 삼각형 노출) + 특수(가늘고 김: 장어형 28×6).
- 도감/획득 화면용 본체: 실루엣 템플릿 7종(유선형, 납작, 둥근, 길쭉, 가오리형, 복어형, 고대어형) × 지느러미 세트 × 색·무늬(줄, 점, 비늘 하이라이트 격자) × 눈 크기.
- 캐시: 물고기 본체는 획득·도감 열 때만 lazy 생성, 사용 후 LRU.

## 6. 환경 · 가구 (아트B)

### 6.1 타일
- 바닥 종류(베타): 잔디, 짙은 잔디(무작위 패치), 흙길, 모래, 얕은 물, 깊은 물, 강둑, 절벽(높이 1~2단), 나무 바닥(실내), 다리.
- **오토타일**: 4비트(상하좌우) 마스크 16변형 + 모서리 보정 4개 = 타입당 최대 20조각. 경계는 직선 금지, 워블 곡선(시드=타일 좌표 해시)으로 "손으로 오린" 가장자리.
- 잔디 디테일: 타일당 시드로 풀잎 0~3포기, 작은 꽃점 확률 8% — 청크 굽기 때 포함(런타임 0비용).
- **물 반짝임**: 물 타일 위에 반짝 선 스프라이트 3종을 시간 기반 위상(타일 해시)으로 α 깜빡 — 화면 내 물 타일당 최대 1개, 화면 전체 최대 60개. 물가 거품 라인은 2프레임 교체(0.6s).
- 강 흐름: 흐름 방향 벡터 타일 데이터(월드팀) 받아 반짝 선을 방향으로 이동.
- 절벽: 윗면 = 잔디 오토타일, 옆면 12px = 흙 띠 + 수평 지층선 2줄 + 하단 AO 그라디언트. 단 아래 바닥에 4px 그림자 띠.

### 6.2 나무·꽃·바위
- 나무 종(베타 4 / 로드맵 10): 활엽수, 과일나무(사과·복숭아·귤·배·체리 — 이름은 그대로 일반명사), 침엽수, 야자.
- 계절 변형: 잎 팔레트 교체 + 봄 꽃 피는 버전, 가을 단풍, 겨울 앙상/눈 덮임. 과일 0~3개 위치 고정 슬롯.
- 흔들기 연출: 캐노피만 회전 ±3° 감쇠 진동 0.5s, 잎 파티클 4개.
- 꽃: 6종 × 4색(베타), 교배색 로드맵. 꽃은 캐시 1장 + 바람 시 하단 기준 skew 흔들림(동시 최대 80).
- 바위 3크기, 광석 바위(반짝 하이라이트), 화석 표시 "균열 별" 마크.

### 6.3 건물 (베타)
- 플레이어 텐트→작은 집(1단계), 마을 상점, 박물관, 주민 집 1종×색 8변형. 건물은 지붕·벽·문·창·굴뚝 파츠 생성기로 조립, 밤에 창문 lighter 조명.

### 6.4 파라메트릭 가구 생성기 (400+ 도달 계획)
- 공식: **기본형(form) × 재질(material) × 색(color)**. 단, 도윤 조건대로 기본형마다 전용 그리기 함수 + 고유 디테일(손잡이, 쿠션 주름, 책등 등).
- 기본형 카테고리(6개월 목표 60개): 의자 8, 테이블 7, 침대 4, 수납 8, 조명 7, 소파 4, 장식(화분·액자·시계·러그) 12, 가전 4, 벽걸이 6.
- 재질 8: 원목밝음, 원목짙음, 흰도장, 파스텔도장, 라탄, 금속, 천(패브릭), 돌. 재질 = {베이스, 그림자, 하이라이트, 결 패턴 함수(나뭇결 줄·라탄 격자·천 점박이)}.
- 색 변형: 기본형당 3~6색(도장·천 재질만 색 변형 적용).
- 계산: 60 기본형 × 평균 유효 재질 2.2 × 평균 색 3.2 ≈ **422종**. 테마 세트(숲속·바다·레트로·꽃) 4세트 × 8피스는 별도 수제.
- 회전: 4방향 중 **정면·측면 2개 그림**(뒤=정면 단순화, 좌=우 반전). 가구 그리드 크기 1×1, 2×1, 2×2.
- 데이터 예:
  ```js
  { id:'chair_round_rattan_cream', form:'chair_round', mat:'rattan', color:'cream', size:[1,1], price:1800 }
  ```
- **베타 서브셋 40종**: 기본형 16(의자3, 테이블3, 침대2, 수납3, 조명2, 장식3) × 2~3변형. 수량은 하우징팀 요구와 최종 조율.

## 10. 베타 vs 6개월 로드맵

### (1) 베타에 들어갈 것
- 아트 헌법 3규칙, 캐시/PX/LRU 코어, 청크 굽기, y-정렬, 그림자 스프라이트.
- 사계절 팔레트 4종 **전부**(실제 시계 게임이라 베타 기간 중 계절이 바뀔 수 있음) + 시간대 오버레이 6키프레임 + 밤 조명.
- 날씨: 맑음·비·눈·벚꽃잎·낙엽.
- 타일 10종 오토타일, 물 반짝임, 절벽 1~2단, 다리.
- 나무 4종(과일 5종 포함) 계절 변형, 꽃 6×4색, 바위 3+광석, 화석 마크.
- 건물 4종(플레이어 집 1단계, 상점, 박물관, 주민 집 8색).
- 아바타: 피부8·헤어10·헤어색12·눈8·상의6·하의4·신발3·모자4, 애니 idle/walk/run/도구3종/줍기.
- 주민 10종, 큐레이션 주민 ≥16명(마을 상주 6~8 + 이사 후보), 감정 8종.
- 곤충 **30**종, 물고기 **30**종(그림자 6단계 + 도감 본체). (6개월 내 각 60+)
- 가구 40종(기본형 16), 아이템 아이콘 자동 생성.
- `tools/art-lab.html` 아트 검수 페이지.

### (2) 6개월 로드맵
- 1~2개월: 곤충·물고기 각 60, 가구 기본형 35·200종, 헤어 20, 의상 형태 2배, 주민 14종, 소나기/뇌우·무지개·안개.
- 3~4개월: 가구 400+ 및 테마 세트 4개, 집 확장 단계별 외관 4단계, 실내 벽지·바닥 생성기(패턴 12 × 색), 계절 경계 블렌드, 반딧불·별똥별 이벤트 연출, 둥근 폰트 도입 검토.
- 5~6개월: 주민 20종·큐레이션 60명+, 축제/계절 이벤트 장식 세트(마을 장식 30), 사진 모드(UI 숨김 + 프레임 스티커), 모자·액세서리 40, 해변/바다 타일 확장, 저사양 모드 2단계.

## 11. 리스크와 대응
1. **"코드 그림이 싸 보인다"** — 아트 헌법 3규칙 + 실루엣 테스트 + art-lab에서 매 주 스크린샷 리뷰(도윤·민규 검토 권한: 반려 가능).
2. **캐시 메모리 폭주(저가 안드로이드 크래시)** — 24M px LRU 상한, `G.art.stats()` 디버그 표시, DPR 2 캡, 계절 전환 시 이전 계절 캐시 전부 해제.
3. **첫 진입 굽기 지연** — 로딩 시 화면 근처 청크·플레이어·주민만 동기 생성(목표 ≤600ms), 나머지는 tickBake 분할.
4. **iOS Safari OffscreenCanvas 미지원/구버전** — 일반 canvas 폴백 공통 코드 경로.
5. **파라메트릭 획일화**(가구·곤충이 다 비슷) — 기본형 전용 디테일 함수 의무, 같은 템플릿 변주는 2축 이상 차이.
6. **IP 유사성** — 동물의 숲식 비례(큰 머리+가는 다리), 특정 캐릭터 색 조합 금지. 체크리스트를 기획팀 리뷰에 포함.
7. **시간대 오버레이로 색 탁해짐** — 밤 보정 lighter, 눈 하이라이트·UI를 오버레이 이후에 그림.
8. **아트 2팀 간 스타일 불일치** — core.js 헬퍼(아웃라인·3톤·워블)를 양 팀이 의무 사용, 팔레트 밖 hex 직접 사용 금지(린트 grep).
