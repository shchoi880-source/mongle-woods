# 2차 교차팀 회의 — 패널 B: 기술 아키텍처 패널

- 참석: **기술 리드(TL)** — 코어·`G` 계약·통합 / **렌더링 엔지니어(RE)** — 캔버스·캐시·프레임 예산 / **툴·QA 엔지니어(QE)** — 세이브·검증·시뮬·개발 도구
- 입력: `BRIEF.md`, r1/r1b 6쌍(기획·아트·경제하우징·월드생태·주민대화·UI사운드) 12개 문서 전체
- 이 문서의 지위: **기술 판정은 최종**이다(§7 결정 요청 항목 제외). 콘텐츠 수치(종 수·확률·가격·대사량)는 각 소유 팀의 데이터 권한이지만, 그 데이터가 **어디에 어떤 형식으로** 있는지는 이 문서가 정한다.
- 표기: `u` = 논리 단위(타일 1/32). `G.x.y()` = 공개 API. 【판정】 = 확정, 【게이트】 = 1주차 벤치 결과로만 뒤집을 수 있음.

---

## 0. 판정 원칙

1. **귀여움을 깎는 절약은 마지막 수단.** 성능 문제는 먼저 품질 티어(§4)로 흡수하고, 기본 품질(High)의 그림은 아트 바이블을 그대로 따른다.
2. **진실 원천은 하나씩**: 시계 1(`G.time`), 시드 1(`seed`), 이벤트 버스 1(`G.on/G.emit`), 데이터 레지스트리 1(`G.data`), 세이브 1(`G.save`), 캐시 회계 1(`G.art.cache`).
3. **결정적 재현**: 같은 세이브 + 같은 게임일 → 같은 날씨·상점·방문객·일일 오브젝트. QA가 버그를 재현할 수 있어야 한다.
4. **인덱스는 추가만(append-only)**: 비트셋에 들어가는 모든 목록(종·형태·재질·색·레시피·여행자·대사)은 `ix` 필드를 명시하고 재배열·삭제를 금지한다(`retired:true`로만 퇴역).
5. **로드 시점에 DOM·캔버스 접근 금지**: 모든 IIFE는 등록만 하고, 실제 초기화는 `G.boot()`가 호출하는 `init()`에서 한다. 그래야 Node에서 `tools/*.js`가 같은 파일을 로드해 시뮬·검증할 수 있다.

## 1. 팀 간 기술 충돌 판정 (T1~T24)

### T1. 타일 크기 — 16px(월드 r1·UI r1) vs 32px(아트·월드 r1b·UI r1b)
- 【판정】 **`G.C.TILE = 32`u.** r1의 "타일 단위" 수치(속도 4.0타일/s, 도망 반경, 충돌 반경 0.3타일 등)는 단위가 타일이므로 **값 변경 없이** 유지된다.
- 근거: 외곽선 1.5u·3톤·눈 하이라이트(r 0.8u)는 16px 타일에서 점이 된다. 화면 픽셀 수(필레이트)는 타일 크기와 무관하고, 화면 내 오브젝트 수는 오히려 32px에서 약 40%로 줄어 y-정렬·drawImage가 싸진다.
- 곤충 가독성 보완은 월드 r1b 규칙 4개(최소 12u, 그림자+반짝 링, 터치 판정 최소 1타일, ★4+ 반짝)를 **엔진 기본값**으로 넣는다.

### T2. 논리 해상도·줌 — 고정 180×320+정수배(UI r1) vs `floor_half`(아트 r1) vs 짧은 변 기준(UI r1b)
- 【판정】 고정 논리 해상도 **폐기**. 줌은 "화면 짧은 변에 보이는 타일 수 `T`"로 정한다.
  ```js
  PX = snap( (shortCssPx * min(devicePixelRatio, tier.dprCap)) / (T * 32), 0.25 )   // 기기px per u
  // T: 세로 폰 11.0 / 가로 폰 9.5 / PC(짧은 변 ≥ 700 CSS px) 12.0 / 태블릿 13.0, 실내 T×0.8
  // 사용자 "시야" 3단: 가까이 T×0.87 / 보통 / 멀리 T×1.15 (연속 줌 금지)
  ```
- 스냅 단위는 UI r1b 안(0.125) 대신 **0.25**: 캐시 키에 PX가 들어가므로 변종 수를 절반으로 줄인다. 0.25 차이는 화면에서 2% 미만의 크기 차라 체감되지 않는다.
- `imageSmoothingEnabled = true`, 캐시는 PX 배율로 1:1 굽기, 그리기 위치 `Math.round(x*PX)/PX` 스냅(아트 r1 §1.3 그대로). 픽셀아트용 `smoothing=false`·정수배는 벡터 스타일과 충돌하므로 기각.
- 하우징 편집 핀치(0.8~1.6×)만 예외: 제스처 중에는 캐시를 스케일해서 그리고(약간 흐림 허용) 손을 뗀 뒤 300ms 후 다시 굽는다.

### T3. 화면 방향 — 세로 고정(UI r1) vs 반응형(UI r1b) vs 가로 기본(월드 r1b)
- 【판정】 **반응형.** 폰은 세로 기본에 가로 회전 허용, PC·태블릿은 창 비율 그대로. `manifest.webmanifest`에 `orientation`을 **쓰지 않는다**.
- 레이아웃 프로필 3개: `G.ui.layout ∈ 'P'(세로 폰) | 'L'(가로 폰) | 'D'(PC·태블릿)`. 화면별 P/L 차이는 CSS 클래스 + 앵커 데이터 1곳에만 둔다.
- 회전: `resize` 150ms 디바운스 → 프로필 교체 → PX가 같으면 캐시 유지, 다르면 `cam:px` 이벤트로 지연 재굽기. 대화·포획·편집 상태는 회전으로 끊기지 않는다(QA R1~R4).
- 월드 r1b의 "가로 기본"은 PC에만 적용한다. 한 손 세로 플레이가 모바일의 주 사용 패턴이라는 UI r1 논거를 유지한다.

### T4. 지면 청크 — 16×16타일(아트 r1·월드 r1) vs 8×8타일(아트 r1b·월드 r1b)
- 【판정】 **`G.C.CHUNK = 8`타일(256u)**, PX 배율로 굽는다. PX 2에서 512²×4B = 1MB/장.
- 유지 집합 = 화면에 걸친 청크 + 바깥 1링. 상한은 티어별로 High 20 / Mid 16 / Low 12장. 마을 112×96 = 14×12 = 168청크는 **필요할 때만** 굽고(1장 ≤ 3ms, `G.idle` 큐), 저장하지 않는다.
- 기각: "논리 해상도로 굽고 확대"(월드 r1) — 벡터 AA가 흐려진다. 64종 바닥 아틀라스(아트 r1) — 타일은 청크 굽기 때만 쓰이므로 메모리만 차지한다.

### T5. 캐시 메모리 예산 — 24M px(아트 r1) vs 8M px(아트 r1b) vs 40MP(UI r1)
- 【판정】 캔버스 메모리는 **하나의 장부**(`G.art.cache`)로 관리한다. 오프스크린 캔버스는 모두 `G.art.cache.alloc(key, w, h, pool)`로만 만든다(직접 `createElement('canvas')` 금지, verify V27이 검사).

| 풀 | High | Mid | Low | 내용 |
|---|---|---|---|---|
| `chunk` | 20M px¹ | 16M | 6M | 지면 청크 |
| `sprite` | 6M | 5M | 3M | 나무·건물·가구·베이크 포즈·생물 big·아이콘(LRU) |
| `room` | 2M | 2M | 1M | 실내 방 정적 캐시(하우징) |
| `ui` | 1M | 1M | 0.5M | 초상 LRU 200, 목록 셀 캔버스 |
| `fx` | 0.5M | 0.5M | 0.3M | 그레이딩 1/4 해상도, 반사, 구름 그림자, 빛 스프라이트 |
| **합계** | **≈ 30M px(≈120MB)** | **≈ 25M** | **≈ 11M(≈44MB)** | iOS 저가 기기는 Low 시작 |

  ¹ 청크 풀은 "장수 × PX²" 상한이다(20장 × 1MB). 사진 모드 1080² 재렌더는 장부 밖 임시 캔버스로 만들고 즉시 해제한다.
- JS 힙 ≤ 80MB, 오디오 샘플 뱅크는 별도 장부(T11). 계절 전환 시 이전 계절 키 전부 해제.

### T6. 캐릭터 — 부위 캐시+transform(아트 r1) vs 실시간 벡터(아트 r1b)
- 【판정】 기본값은 **실시간 벡터**이고, 화면 내 캐릭터가 티어 상한(High 12 / Mid 8)을 넘거나 Low 티어이면 **포즈 양자화 베이크**(방향 3 × 걷기 8위상 × 아이들 4위상 = 36장/캐릭터, 56×56u)로 자동 전환한다. 눈 하이라이트·볼터치·감정 아이콘은 베이크 모드에서도 매 프레임 실시간으로 그린다.
- API는 하나: `G.art.actor.draw(ctx, actor, t)`가 내부에서 경로를 고른다. 주민 AI·플레이어 코드는 어느 쪽인지 모른다.
- 【게이트】 W1 벤치 S1에서 기준 기기(갤럭시 A2x급) 실시간 벡터 캐릭터 1명이 **0.15ms를 넘으면** Mid의 기본값을 베이크로 바꾼다. 부위 캐시+transform 방식은 화질(아웃라인 두께가 출렁이고 접합부에 AA 틈이 생김) 때문에 벤치 결과와 관계없이 기각한다.

### T7. 절벽 높이 1단 — 12u(아트 r1) vs 16u(월드 r1b)
- 【판정】 **`G.C.HSTEP = 16`u(반 타일).** 그리기 y 오프셋 = `z * 16`.
- 근거: 오토타일·경사로 조각이 반 타일 격자에 맞고, 정렬키·충돌 계산이 정수로 떨어진다. 고지대 해금 때 "올라간 느낌"도 산다.
- 아트 절충: 옆면 16u 중 **위 4u는 윗면 잔디가 넘어온 립(lip)**, 아래 12u를 흙 띠 + 지층선 2줄 + AO로 쓴다. 아트 r1이 원한 12u 흙 옆면이 그대로 보인다.

### T8. 마을 크기 — 64×48(기획 r1) / 72×56(기획 r1b) / 112×96(월드)
- 【판정】 엔진 상한은 128×128. 베타 본 맵은 **112×96**(월드 r1·r1b 합의)이고, 기술 쪽에서 막을 이유는 없다(지형 세이브 RLE 3~5KB, 청크는 지연 굽기). 조건: 월드 r1b의 "빈 공간 금지" 검사를 생성 검증에 포함할 것. 이후 새 지역(안개 연못·동굴·구름 정원)은 본 맵을 늘리지 않고 **별도 area**(≤ 48×48)로 만든다.

### T9. UI 렌더 — 캔버스 HUD(UI r1/r1b) vs DOM 목록(UI r1b)
- 【판정】 **2층 구조**: `#world` 캔버스 1장 + `#ui` DOM 루트 1개.
  - **캔버스**: 월드와 월드에 붙는 것(감정 말풍선, 아이템 들어 올리기, 이름표, 낚시 찌, 조준 링, 하우징 그리드).
  - **DOM**: HUD(시계·화폐·버튼·조이스틱 표시), 토스트, 대화창, 잎첩과 모든 앱, 상점, 시트, 입력창.
- 근거: HUD는 분 단위로만 바뀌므로 DOM이면 프레임 비용이 0에 가깝다. 고DPR에서 글자가 선명하고, `env(safe-area-inset-*)`, 글자 크기 3단계, 한글 IME, 네이티브 관성 스크롤을 공짜로 얻는다. UI r1b가 HUD를 캔버스로 둔 이유는 폰트 로딩이었는데, T10으로 해결된다.
- 규칙: DOM은 **변경 시에만** 쓴다. 매 프레임 쓰는 것은 조이스틱 노브 `transform` 하나뿐이다. 대형 목록은 `G.ui.VList`(행 풀 + 행마다 `<canvas>` 1개 재사용)로 만든다. **dataURL 아이콘 금지**(아트 r1 `iconURL` 기각): 셀 캔버스에 `G.art.drawIcon`으로 직접 그린다.
- 잎첩이 열려 있으면 월드는 30fps로 그린다(시뮬레이션은 60Hz 유지).

### T10. 폰트 — 시스템 폰트(아트 r1·UI r1) vs 둥근 폰트 1종(UI r1b)
- 【판정】 **베타에 OFL 둥근 한글 폰트 1종을 넣는다.** KS X 1001 2,350자 + ASCII 서브셋, woff2 ≤ 350KB, `fonts/`에 같이 배포(상대 경로), 서비스 워커가 미리 캐시, `font-display: swap`. 실패하면 `system-ui, "Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans KR", sans-serif`로 대체한다. 라이선스 원문(`fonts/OFL.txt`)을 함께 배포한다.
- 캔버스 글자(이름표·도장)는 `document.fonts.ready` 뒤에 굽는다. 폰트 후보 2종은 UI팀이 W1에 제출하고, 총괄이 라이선스를 확인한다(§7).

### T11. 오디오 — 실시간 오실레이터(사운드 r1) vs 오프라인 샘플 뱅크(사운드 r1b)
- 【판정】 **샘플 뱅크를 채택**하되 베타 범위를 줄인다. 굽는 악기는 칼림바·마림바·펠트 피아노·플럭·베이스·퍼커션 6종이고, 플루트만 실시간(동시 2성)이다.
- 굽기: `OfflineAudioContext(1ch, 22050Hz)`. 플럭(카플러스-스트롱)처럼 JS 루프로 만드는 샘플은 `G.idle`에서 **프레임당 2ms 이하로 쪼개** 계산한다.
- 뱅크 메모리: High/Mid ≤ 16MB(벨로시티 2층), Low ≤ 8MB(1층). 계절 악기는 교체해서 굽는다.
- 뱅크가 준비되기 전에는 간이 실시간 보이스로 대신 연주한다(타이틀 화면에서 핵심 3종을 먼저 굽는다).
- 스케줄러: 25ms 틱, 120ms 룩어헤드. 활성 노드 ≤ 80. 원샷 노드는 `onended`에서 `disconnect`한다.

### T12. 세이브 형식 — 개별 키(월드 `w.*`) vs 단일 엔벨로프(UI r1)
- 【판정】 슬롯 1개 = 엔벨로프 JSON 문자열 1개. A/B 교대 기록 + FNV-1a 체크섬(UI r1 그대로). 각 모듈은 `G.save.section()`으로 자기 섹션만 등록하고, localStorage를 직접 만지는 것은 `save.js` 하나뿐이다(§3).
- 대형 컬렉션은 `kind:'bitset'`(런타임 `Uint32Array` → 바이트 → RLE → base64).
- 용량: 슬롯당 **160KB 상한, 120KB에서 경고**(UI r1b). 기획 500KB·UI r1 300KB 안은 A/B 2슬롯 + 마이그레이션 백업 + 여유를 감당하지 못한다.
- A/B는 충돌 대비용이지 사용자 세이브 슬롯이 아니다. 베타는 **브라우저당 마을 1개**이고, 다중 마을은 로드맵에서 키 접두 `mg.v{n}.`으로 확장한다.

### T13. 가구 엔트리 ID — `form*100+mat*10+color`(경제) vs 19비트 `form<<9|mat<<5|color`(아트) vs 미정(UI)
- 【판정】 **`entry = form * 256 + mat * 16 + color`**(재질 ≤ 16, 색 ≤ 16, 형태 ≤ 1,024).
- 근거: 경제 10×10과 아트 12재질×16색을 둘 다 담고, 비트 연산(`entry>>8`, `(entry>>4)&15`, `entry&15`)으로 바로 분해된다. 형태마다 256칸을 예약해도 RLE가 0 구간을 압축하므로 세이브 비용은 보유 수에 비례한다(형태 620개 원시 19.8KB → 6개월 하드코어 실측 추정 3~6KB). 런타임 비트셋 20KB는 문제없다.
- 유효 조합은 형태마다 `matMask`(16bit) + 재질별 `colorMask`(16bit)로만 정의한다. 60,000행짜리 테이블은 만들지 않는다. 경제의 `val` 배율(재질 `mul`·색 `mul`)도 재질·색 테이블에 둔다.

### T14. 생물 도감 인덱스·변이 enum
- 【판정】 `dexIx = species.ix * 6 + v`, `v`: **0 일반 · 1 거대 · 2 알비노 · 3 희귀무늬 · 4 황금 · 5 계절색**(월드생태 r1 §11.6 순서). UI r1b의 "작은/큰/색A/색B/반짝" 정의는 기각. 바다생물도 6칸을 예약한다(베타에서는 0·1만 쓰고 나머지는 예약).
- 변이 확률은 생태 r1, 경제 r1b, 아트 r1b가 서로 다른 값을 냈다. **`data/variants.js` 한 파일**(소유: 시간·생태)에 확률·조건 배수·판매 배율·연출 등급 열을 모두 두고 다른 팀은 읽기만 한다. 최종 수치는 `tools/eco-sim.js` + `tools/econ-sim.js` 결과로 W3에 확정한다.

### T15. 시간·날짜 경계
- 【판정】 시계는 `G.time` 하나뿐이다. `Date.now()`/`new Date()`는 `time.js` 밖에서 쓰지 않는다(verify V26).
  - **게임일 경계 = 기기 로컬 05:00.** `day = 로컬 날짜(now − 5h)를 날짜 성분으로 계산한 epoch 일수`. 날짜 문자열 기반이라 DST 23/25시간도 안전하다. 주 = 월요일 05:00 시작. 계절은 월 표 + 반구(새 게임에서만 고름).
  - 시간 역행: `maxDay`, `lastRefreshDay`를 저장한다. 일일 보상·리스폰은 `day > lastRefreshDay`일 때만 준다. 역행해도 처벌은 없다(전 팀 합의).
  - 카운터 2개를 명시적으로 구분한다: `G.time.elapsedDays()`(생성일부터 `maxDay` 기준, 단조 증가)는 **스토리 아크·입주·뉴스**에 쓰고, `G.time.playDays()`(실제로 접속한 서로 다른 게임일 수)는 **집 증축 게이트**에 쓴다(경제 r1b 익스플로잇 대응).
  - 앞으로 점프하거나 앱이 백그라운드에서 돌아오면 `time:day {day, prev, skipped}`를 **한 번만** 발행한다. 각 모듈은 `skipped`로 캐치업한다(나무 성장 min(n,4) 등).
  - 개발 오프셋: `G.time.setOffset(ms)`, `G.time.setRate(k)`. 개발 모드에서 오프셋이 0이 아니면 세이브는 샌드박스 키로 간다(§5).

### T16. 시드
- 【판정】 새 게임에서 `seed`(uint32)를 하나 만들고, 이것이 곧 세이브 ID다. 모든 결정적 난수는 여기서 파생한다.
  ```js
  G.rng.stream(...keys)   // = mulberry32(hash32(seed, ...keys)), 키는 문자열·정수
  // 예약 키: 'gen'(지형, + genVersion) · 'map',0..2(지도 3장 후보) · day,'wx'(날씨) · day,'shop' · day,'wind'(유행 바람)
  //          day,'daily'(화석·조개·일일 오브젝트) · day,'visit'(방문객 편성) · day,'news' · day,hour,'bgm' · day,vid,'concern'
  G.rng.play   // 비결정 게임플레이 난수(포획 성공·변이 판정 등) — 세션별 시드
  G.rng.fx     // 연출 전용(Math.random 래퍼). 파티클·깜빡임
  ```
- 모든 키 문자열은 `G.rng.KEYS` 목록에 등록한다. verify가 오타·충돌을 검사한다.
- 방문객: 아트 r1b의 원칙대로 **런타임에서 임의 시드로 외형을 생성하지 않는다.** `data/travelers.js`는 아트 승인 파이프라인을 통과한 시드 테이블(append-only, 베타 500개)이고, `visitorIx` = 그 테이블 인덱스다(대화 r1의 `visitorId`). 그날 누가 오는지는 `stream(day,'visit')`이 인덱스를 고르는 것으로 정한다. 이름·성격·목소리는 그 시드에서 결정적으로 만든다.

### T18. 입력 상수

### 2.4 공유 `G` 계약

**A. 게임 루프** — `requestAnimationFrame` 1개, `dt = min(now−last, 50ms)/1000`.
- 단계 순서: `time`(분·시·일 경계 검사) → `input` → `sim`(최상단 `world:true` 씬과 그 아래 씬들의 `update`) → `late`(카메라·청각 리스너) → `draw`(캔버스) → `ui`(DOM 갱신 대기열 flush) → 남는 시간에 `G.idle`(티어별 예산: High 3ms / Mid 2ms / Low 1.5ms).
- 백그라운드 탭에서는 루프와 오디오를 멈추고(`visibilitychange`), 돌아오면 `G.time`이 캐치업한다.

**B. 씬 스택**
```js
G.scene.define(id, { enter(args), exit(), pause(), resume(), update(dt), draw(ctx), input(ev)→handled,
                     world:true|false /*월드 시뮬 계속*/, opaque:true|false /*아래 씬 그리기 생략*/, ui:false|true /*DOM 패널*/ });
G.scene.push(id,args) / pop(result) / replace(id,args) / top() / is(id)
// 정의된 씬: title, create, town, interior, edit, dive, sky, cutscene(캔버스) / notebook, shop, dialog(ui:true)
```
- 실시간 게임이므로 `notebook`·`dialog` 위에서도 `G.time`과 주민 일과는 계속 흐른다. 막히는 것은 플레이어 입력뿐이다.

**C. 입력 이벤트** — `ev.type ∈ act | actHold | actUp | tool | toolNext | toolPrev | menu | back | tapWorld{wx,wy} | pinch{scale} | pan{dx,dy}`. 이동은 매 프레임 `G.input.move = {x,y,mag}`를 읽는다. 연출 중에는 `G.input.lock('script')`.

**D. 엔티티 모델** — 클래스 없이 평범한 객체를 쓴다. 매 프레임 할당 금지(풀 재사용).
```js
{ id, kind:'player'|'villager'|'visitor'|'bug'|'fish'|'sea'|'item'|'fx', area:'town',
  x, y,        // 월드 u, 발밑 중심 (원점 = 맵 좌상단, +y = 남쪽)
  z,           // 지면 높이 단 0~2 (그릴 때 y − z*HSTEP)
  h:0,         // 공중 높이 u (점프·비행·들어 올리기) → 그림자 축소
  r,           // 충돌·선택 반경 u (플레이어 9.6 = 0.3타일)
  dir:0..3,    // 0 아래 · 1 왼쪽 · 2 위 · 3 오른쪽
  shadow:18,   // 그림자 폭 u (0 = 없음)
  vis:true, sb:0 /*정렬 보정 −8..+8u*/, sy:0 /*렌더 전용, 쓰기 금지*/ }
G.ent.add(e) / remove(e) / get(id) / query(x,y,r,mask,out) / inRect(rect,mask,out) / each(kind,fn)
G.ent.K = { PLAYER:1, VILLAGER:2, VISITOR:4, BUG:8, FISH:16, SEA:32, ITEM:64, FX:128 }
```
- 나무·바위·꽃·건물·가구는 엔티티가 아니다. 월드·하우징의 압축 저장소에 두고, 렌더 provider가 보이는 것만 내보낸다(엔티티 수 ≈ 화면 내 30 이하 유지).

**E. 좌표계** — 맵은 영역(area)마다 독립 격자다(`town`, `house`, `shop`, `museum`, `vh:<vid>`, 로드맵 `fog`, `cave`, `sky`). 타일 `tx = floor(x/32)`. 화면 변환은 `sx = (x − cam.x)·PX`, `sy = (y − z·16 − h − cam.y)·PX`(기기 px). 시간은 실시간 ms이고, 모든 이동 속도는 타일/s 상수(`data/world.js`)를 쓴다. 애니 주기는 속도에서 유도한다(걷기 4.0타일/s ↔ 사이클 460ms 기준 비례).

**F. 그리기 순서(y-정렬 규약)**

| 레이어 | 내용 | 정렬 |
|---|---|---|
| 0 GROUND | 청크(절벽 옆면 포함) | — |
| 1 DECAL | 물 애니·거품·조수 띠·웅덩이·발자국·구멍·러그(실내) | 없음 |
| 2 SHADOW | 모든 엔티티·오브젝트의 접지 그림자(실루엣 밖) | 없음 |
| 3 SORT | 나무·바위·건물·가구·캐릭터·생물·떨어진 아이템 | `sy = 발밑 y(u) + sb`, 같으면 x. 여러 칸 오브젝트는 **발자국 앞(남쪽) 가장자리 y** |
| 4 CANOPY | 반투명 전경(캐노피가 플레이어를 가릴 때 α0.5) | — |

| 6 GRADE | 시간대 그레이딩 1패스 | — |

```js

```
- 정렬은 지난 프레임 순서를 재사용하는 삽입 정렬(거의 O(n))이다. 높은 단 위의 오브젝트는 발밑 y가 더 북쪽이므로 별도 규칙 없이 앞뒤가 맞는다.

### 3.3 섹션 등록 API
```js
G.save.section('collect', {
  v: 1, kind: 'json',            // 'json' | 'bitset'(필드 단위 지정 가능) | 'packed'
```

### 3.5 마이그레이션 규칙
1. 엔벨로프 `v`와 섹션 `v`는 독립이다. 섹션 마이그레이션은 n→n+1 순수 함수만 허용하고, 실행 전 `mg.premig`에 원본을 백업한다.
2. 필드는 삭제하지 않고 사용 중단만 한다. 모르는 섹션은 그대로 보존해서 다시 쓴다(미래 버전 호환).
3. 세이브가 현재 앱보다 미래 버전이면 **읽기 전용** 경고를 띄우고 새로고침을 권한다. 절대 덮어쓰지 않는다.
4. `catVer`가 바뀌면 데이터 인덱스 재매핑 표(`data/*.js`의 `remap[catVer]`)를 적용한다(append-only 원칙을 지키면 표는 비어 있어야 한다).
5. 마이그레이션 테스트용으로 각 버전의 샘플 세이브(`tools/fixtures/save-v1-*.txt`)를 영구 보관하고, verify V8이 최신 버전까지 왕복시킨다.

### 3.6 내보내기 형식
- 문자열: `MG1:` + base64(UTF-8(엔벨로프 JSON)) + `:` + fnv1a(본문). 베타는 압축하지 않는다. 로드맵에서 `MG2:`(LZ) 접두로 추가한다.
- 파일: `몽글숲_<마을명>_YYYY-MM-DD.mgsave`(내용 = 위 문자열). `Blob` + `<a download>`를 쓰고, iOS는 `navigator.share({files})`로 대체한다.
- 가져오기: 검증 → 요약 미리보기(마을·플레이 일수·화폐·도감 종/변이 수) → 2단계 확인. 덮어쓰기 직전에 현재 세이브 내보내기를 자동으로 제안한다.
- 7일 이상 내보내기를 안 했으면 잎첩 설정 앱에 배지를 단다(사파리 저장소 정리 정책 대비).

### 6.3 버티컬 슬라이스(M2) 정의 — "하루 한 바퀴"
- **흐름**: 타이틀(첫 탭 오디오 언락) → 캐릭터 만들기(파츠 축소판 + 이름 DOM 입력) → 지도 3장 중 선택 → 보리 할멈 도착 대사 → 텐트 설치 → 첫 배달 → 낚시 → 곤충 → 상점 판매·구매 → 화석 발굴 → 텐트 꾸미기 가구 3개 → 첫날 밤 연출.
- **포함**: 마을 112×96 1개(스탬프 4종), 텐트 실내 1, 상점 실내 1. 주민 3명(딸랑·소금·라임: 일과·대화 각 40줄·친밀도·선물). 곤충 12·물고기 12·화석 6(변이 6종 판정과 연출 등급 전부). 아이템 60, 가방 20칸, 화폐·유행 바람(태그 10)·상점 회전, 가구 기본형 8 × 재질 2 × 색 3(엔트리 ID·카탈로그 비트셋), 하우징 편집(배치·회전·Undo). 05:00 리셋(화석·조개·날씨·상점 재생성), 시간 역행 규칙. 콩알 꼬물 반응, 편지 1종 + 배달. HUD + 잎첩(가방·도감·설정). 오디오: 모티프 2개 + 효과음 15 + 옹알이 목소리. 세이브 A/B·내보내기·가져오기, PWA 오프라인.
- **합격 기준**: ① 기준 기기 A·B에서 High 또는 Mid 티어로 p90 ≤ 16.6ms ② 첫 30분 동안 예외·경고 0 ③ 앱 강제 종료 후 재실행 시 손실이 직전 이벤트 이하 ④ 디버그 패널로 7일을 건너뛰어도 일일 리스폰·편지·날씨가 결정적으로 재현됨(V12) ⑤ verify 전 항목 통과 ⑥ 사내 테스터 5명 중 4명이 "낚시·곤충 손맛 만족"(월드 r1 도현 기준).

### 6.4 베타 전체(M3~M4) 범위
- 각 팀 r1b "베타" 절을 그대로 범위로 삼고, 이 문서의 판정을 우선한다. 기술 쪽에서 추가로 확정하는 항목:
  - 순차 입주 8명, 여행자 하루 1~3명(승인 시드 500), 사건 엔진·콩자 일보, 이벤트 엔진 + 마이크로 6 + 정례 2, 등불 1~2.
  - 둥지 약정 0~2단계(3단계는 `G.flags.beta2`), 아늑지수 v2, 사진 모드 기본(β2 플래그).
  - 수영·잠수, 조수, 밤하늘 수첩, 서식지 점수, 곤충 행동 10유형, 겨울 계절 변신 풀세트(출시 시점 우선).
- 기능 플래그 `G.flags`(코드는 넣고 끄기): `moveOut`(주민 전출), `inviteVisitor`(초대 입주), `beta2`(집 3단계·사진), `reflection`(티어와 별개 강제 끄기).
- 통합 규칙: 매일 18시 통합 빌드. `node tools/verify.js` 실패 PR은 머지 금지. `G` 계약이나 데이터 스키마 변경은 W1 이후 "RFC 1페이지 + TL 승인"으로만 가능. 이벤트·테이블을 추가할 때는 `G.EV`·`G.data.table` 선언을 먼저 머지한다.
