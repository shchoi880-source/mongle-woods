# 1차 회의 반론 제안서 — 아트 2조 (테크니컬 아티스트 + 일러스트레이터)

- 작성: 아트 2조 **TA 지오**(성능·파이프라인·셰이딩 수식) / **일러스트 새봄**(비례·표정·연출·귀여움 판정)
- 검토 대상: `docs/meetings/r1-아트.md`(아트 1조 합동안), `docs/meetings/r1-기획.md`, `docs/BRIEF.md`
- 오너 피드백: "계획이 얇다." 목표 = **2D 코드 드로잉으로 동물의 숲급 매력**, 중저가 폰 60fps.
- 이 문서의 입장: 1조 안의 뼈대(벡터+굵은 아웃라인, 캐시, y-정렬, 오버레이 조명)는 **유지**한다. 문제는 "귀여움을 만드는 숫자"가 거의 없고, 몇몇 성능 결정이 **반대 방향으로 틀렸다**는 것. 아래는 ①조목별 비판 ②아트 바이블(px 단위) ③애니메이션 바이블 ④환경 밀도 ⑤품질 게이트·아트랩 ⑥생성기 파라미터 표와 베타 수량 상향.

## 1. 1조 안 조목 비판과 수정안

### 1-1. "부위 캐시 + transform 합성"은 싸 보이고, 생각보다 이득도 없다 (§2·4.1 반론)
- **화질 문제**: 캐시는 PX 배율에 맞춰 1:1로 그려야 선명하다(1조 스스로 §1.3에서 "스케일 1:1만 허용"이라 적었다). 그런데 스쿼시(scaleY 0.94)·팔 회전·머리 기울기(±6°)는 전부 비-1:1 변환이다. 결과: 숨쉬기 바운스마다 아웃라인 두께가 0.1px씩 출렁이고, 눈 하이라이트(지름 1.6px)가 반투명 얼룩이 된다. **귀여움의 핵심인 눈이 가장 먼저 망가진다.**
- **이음매 문제**: 부위가 분리된 비트맵이면 몸-팔, 머리-귀 접합부에서 안티앨리어싱 틈(밝은 실선)이 생긴다. "외곽 확장 채움"은 한 path 안에서만 효과가 있다.
- **비용 재계산**(TA 지오 추정치, 베타 1주차 실측으로 확정): 캐릭터 1명 = 아웃라인 실루엣 1 stroke + 채움 약 14 fill + 얼굴 약 10 fill + 그림자 1 drawImage ≈ 26콜. 중저가 안드로이드(스냅드래곤 6xx급)·DPR 2에서 소형 path fill 1콜 ≈ 3~5µs → 캐릭터 1명 0.10~0.15ms, **화면 내 10명 ≈ 1.0~1.5ms**. 1조가 잡은 "캐릭터 합성 2.0ms" 안에 들어온다.
- **수정안**: 
  1. 화면 내 캐릭터 ≤12명이면 실시간 벡터.
  2. 13명 이상이거나 저사양 모드(fps<50이 3초 지속)면 **포즈 양자화 베이크**로 전환: 방향 3 × 걷기 8위상 × 아이들 4위상 = 36장/캐릭터, 각 56×56 PX배율(=112² 기기px). 스쿼시·기울기는 베이크 시점에 적용(런타임 변환 없음).
  3. 눈 하이라이트·볼터치·감정 아이콘은 베이크 모드에서도 **실시간으로 위에 찍는다**(눈이 생명).

### 1-2. 청크·캐시 메모리는 폰을 죽인다 (§2.1 반론)
- 16×16타일 청크 = 512 논리px → PX 2에서 1024×1024×4B = **4MB/장**, 9장 36MB. 여기에 24M px LRU 상한(96MB)을 더하면 저가 iPhone(2~3GB RAM)에서 Safari가 탭을 리로드한다.
- **수정안**:
  - 청크 = **8×8타일(256 논리px, PX2에서 512² = 1MB)**. 화면(가로 11~13타일 × 세로 ~22타일)을 덮으려면 2×4 = 8장, +1링 프리페치로 최대 16장 = 16MB.
  - 전체 캐시 상한 **8M px(32MB)**, 저사양 4M px. `G.art.stats()`를 디버그 HUD에 상시 표시.
  - 바닥 64종 아틀라스(2048²=16MB)는 **폐기**: 타일은 청크 굽기에서만 쓰이므로 굽기 시 path로 바로 그리면 된다. 아틀라스는 메모리만 먹는다.
  - 굽기 1청크 예산 ≤3ms(잔디 디테일 포함). 걷는 속도(4타일/s)면 청크 경계를 2초에 1번 넘으니 tickBake 4ms로 넉넉하다.

### 1-3. 워블은 장소를 가려야 한다 (헌법 3조 수정)
- 얼굴에 워블을 주면 좌우 눈 높이가 0.3px 어긋나 "사시"처럼 보인다. 손으로 그린 맛은 **실루엣과 지면 경계**에서만 필요하다.
- 수정된 워블 규칙:
  | 대상 | 워블 진폭 | 제어점 간격 |
  |---|---|---|
  | 얼굴 파츠(눈·코·입·볼) | 0 | — |
  | 캐릭터 실루엣(머리·몸) | 0 (대신 의도된 비대칭: 머리 ry를 좌우 0.3px 다르게 — 새봄 지정) | — |
  | 나무 캐노피·바위·덤불 | ±0.35px | 6~8px |
  | 지면 경계(물가·모래·절벽) | ±0.8px (저주파) + ±0.25px(고주파) | 16px / 4px |
  | 가구 | 0 (직선이 생명; 대신 모서리 반경으로 부드러움) | — |

### 1-4. 셰이딩·아웃라인 "% 감산"은 극단 색에서 무너진다
- 흰 양·판다 흰 털·눈 덮인 지면은 명도 −45% 해도 회색(L≈50) 외곽 → 탁함. 검은 머리카락(L≈15)은 0 이하. §2-3에 비선형 공식으로 교체.

### 1-5. 시간대 오버레이: 패스 수를 줄이고 "탁함"을 구조적으로 해결
- 1조: multiply 1 + 비네트 1 + 밤 보정 lighter 1 + 조명 n. DPR2 폰(390×844 CSS → 780×1688 = 1.3M px)에서 풀스크린 합성 1패스 ≈ 0.4~0.9ms. 3패스면 아트 예산의 1/4.
- **수정안**: 시간대 키프레임마다 **그레이딩 캔버스 1장을 1/4 해상도(195×422)로 프리베이크** — multiply 색 + 비네트 + 상단 하늘빛 그라디언트(위쪽이 약간 더 푸름)를 한 장에 합성. 런타임은 `globalCompositeOperation='multiply'`로 확대 drawImage 1회(부드러운 그라디언트라 확대해도 무손실). 키프레임 사이 보간은 인접 2장을 α 블렌드해 **1분에 1번** 재베이크(작은 캔버스라 0.3ms). → **풀스크린 1패스 + 조명 스프라이트**.
- 밤의 "탁함"은 multiply 색이 저채도라서다. 밤 색을 #5A5F9E → **#6E74C4**(채도↑)로, 대신 지면 팔레트 쪽에서 밤 전용 처리 불필요. 캐릭터 눈 하이라이트·창문·반딧불은 오버레이 **후**에 그린다(1조와 동일, 유지).

### 1-6. 곤충·물고기: 작으면 귀엽지 않다
- 곤충 월드 크기 8~14px → **12~20px**(나비 날개 폈을 때 18px). 실제 비율보다 2배 과장. 날갯짓은 2프레임 교체가 아니라 `scaleX = |sin(t·f)|` 연속(실시간 path, 곤충은 화면에 ≤6마리).
- 물고기 그림자: 1조의 6단계 유지 + **그림자 꼬리 흔들기**(그림자 타원 뒤쪽 1/3을 skew ±0.15, 2Hz) — 이게 없으면 "검은 콩"이 미끄러진다.

### 1-8. 1조 안에서 그대로 채택하는 것
- 둥근 벡터 + 굵은 동계열 아웃라인, 3톤, 그림자 스프라이트(shadowBlur 런타임 금지), y-정렬 삽입 정렬, DPR 2 캡, 파티클 풀(할당 0), 사계절 팔레트 4종 전부 베타 포함, 파라메트릭 주민 + **수제 큐레이션만 등장**, 실루엣 테스트, 아이콘 = 같은 렌더 함수 `mode:'icon'`.

### 2-5. 워크드 예시 ① 주민 1명(토끼 "모찌") 그리기 — 실시간 벡터
```js
function drawVillager(ctx, p, pose, x, y, dir){            // p = 큐레이션 params, pose = 애니 결과
  const C = p._colors;                                      // 사전 계산: base/shadow/light/outline (hsl→문자열 캐시)
  ctx.save(); ctx.translate(x, y);
  G.art.drawShadow(ctx, 0, 0, 20 * pose.shadowScale, 0.28); // 1) 그림자 스프라이트(실루엣 밖)
  ctx.translate(0, pose.bobY);                              // 2) 걷기 상하
  ctx.scale(pose.sx, pose.sy);                              // 3) 스쿼시(발밑 기준이라 원점 유지)
  // 4) 실루엣 path 1개로 머리+몸+귀+발 합성 → 외곽 확장 채움
  const sil = p._silPath[dir];                              // Path2D, params당 방향별 1회 생성(포즈 무관 부분)
  ctx.lineWidth = 3.5; ctx.strokeStyle = C.outline; ctx.stroke(sil);  // 1.75 × 2
  ctx.fillStyle = C.base; ctx.fill(sil);
  // 5) 귀: 각도는 pose.earL/earR(스프링). 귀는 별도 Path2D, 회전 후 같은 레시피
  for (const s of [-1, 1]) {
    ctx.save(); ctx.translate(s*4.5, -35); ctx.rotate(s*0.21 + (s<0?pose.earL:pose.earR));
    ctx.stroke(p._ear); ctx.fill(p._ear);
    ctx.fillStyle = C.earInner; ctx.fill(p._earInner);      // 안쪽 분홍, 외곽선 없음
    ctx.restore(); ctx.fillStyle = C.base;
  }
  // 6) 3톤: 머리 clip 안에서 그림자 초승달 + 하이라이트
  ctx.save(); ctx.clip(p._headPath);
  ctx.fillStyle = C.shadow; ctx.fill(p._headShadeCrescent, 'evenodd');
  ctx.fillStyle = C.light;  ctx.fill(p._headHi);
  ctx.restore();
  // 7) 주둥이·패턴(배 무늬) — 외곽선 없이 innerLine 0.75 하단만
  ctx.fillStyle = C.muzzle; ctx.fill(p._muzzle);
  // 8) 얼굴: 깜빡임 pose.eyeOpen(0~1)은 ry 스케일, 0.15 미만이면 호(arc)로 교체
  drawEyes(ctx, p.eyes, pose.eyeOpen, pose.lookX);         // lookX: 시선 ±0.8px (플레이어 방향)
  drawNose(ctx, p.nose); drawMouth(ctx, pose.mouth);        // 말하기: 2프레임 'o'/'∪' 90ms 교대
  ctx.fillStyle = C.cheek; ctx.globalAlpha = 0.55; ctx.fill(p._cheeks); ctx.globalAlpha = 1;
  // 9) 팔: 몸 앞에 캡슐 2개(rot = pose.armL/R)
  // 10) 의상: 몸 clip 안에서 상의 채움 + 밑단 innerLine
  ctx.restore();
  // 11) 감정 아이콘은 오버레이 후 UI 패스에서(빛 영향 X)
}
```
- 콜 수: stroke 3 + fill ~22 + clip 2 ≈ 27. Path2D는 params 로드 시 1회 생성 → 프레임 할당 0.

### 3-1. 공통 이징·스프링 (전 팀 공용 `G.art.ease`)
```js
const E = {
  outQuad:t=>1-(1-t)*(1-t), outCubic:t=>1-Math.pow(1-t,3), inQuad:t=>t*t,

  outElastic:t=>t===0||t===1?t:Math.pow(2,-10*t)*Math.sin((t*10-0.75)*2.0944)+1,
};
// 감쇠 스프링(프레임 독립): 귀·꼬리·과일·모자 위 '콩알'
function spring(s, target, k, c, dt){ const a = k*(target-s.x) - c*s.v; s.v += a*dt; s.x += s.v*dt; }
// 감쇠 진동(이벤트 1회성): A·e^(-t/τ)·sin(2πt/T)
const wobble=(t,A,tau,T)=>A*Math.exp(-t/tau)*Math.sin(2*Math.PI*t/T);
```

## 4. 환경 밀도 — "가만히 있어도 살아 있는 화면"

### 4-1. 지면 디테일 (청크 굽기에 포함 → 런타임 0ms)
- 분포: **지터 격자 포아송 근사** — 타일을 4×4 서브셀(8px)로 나누고, 서브셀마다 해시로 1개 후보점 + 확률 판정. 군집감은 저주파 값 노이즈(주기 6타일)로 확률 가중.
```js
const h32=(x,y,s)=>{let h=(x*374761393+y*668265263+s*2246822519)|0;h=Math.imul(h^(h>>>13),1274126177);return ((h^(h>>>16))>>>0)/4294967296;};
function scatter(tx,ty,kind,seed,emit){                 // emit(px,py,variant)
  const k=G.art.scatterTable[kind], cl=valueNoise(tx/6,ty/6,seed);     // 0~1 군집
  for(let sy=0;sy<4;sy++)for(let sx=0;sx<4;sx++){
    const gx=tx*4+sx, gy=ty*4+sy, r=h32(gx,gy,seed);
    if(r < k.density*(0.4+1.2*cl)) emit(gx*8+h32(gx,gy,seed+1)*8, gy*8+h32(gx,gy,seed+2)*8, (r*997|0)%k.variants);
  }
}
```

### 4-3. 바람 (전역 1개 함수, 모든 흔들림이 공유)
```js
G.art.wind = { base:0.3, gust:0, dir:1 };            // 날씨팀이 base 설정(맑음 0.3, 바람 0.9)
function windAt(x, t){                                  // 결과 -1~1
  const w = G.art.wind, ph = x*0.013;
  const slow = Math.sin(t*0.0009 + ph) * 0.6 + Math.sin(t*0.0023 + ph*1.7) * 0.4;
  const gustWave = w.gust * Math.max(0, Math.sin((x*0.004 - t*0.0006)*Math.PI)); // 돌풍이 화면을 가로질러 이동
  return w.dir * (w.base*slow + gustWave);
}
// 꽃: ctx.setTransform(PX,0, PX*0.18*windAt(x,t), PX, x*PX, y*PX); drawImage(flower, -ox, -oy)  // 발밑 기준 skew
```
- 돌풍: 평균 18s마다(바람 날 6s) 2.5s짜리 gust 0→1→0. 돌풍 때 낙엽·꽃잎 파티클 스폰율 ×3, 나무 캐노피 미세 회전 ±1°(캐시 비트맵 회전 → 나무는 1:1 예외 허용: 캐노피는 부드러운 형태라 흐림이 눈에 안 띔, 새봄 승인).
- 흔들리는 대상: 꽃(skew 0.18), tall 풀 소품(0.3), 나무 캐노피(±1°), 깃발·빨래(로드맵), 물 반짝임 이동 방향. **바닥 풀포기(청크)는 정적** — 대신 플레이어 주변 반경 2타일에 "살아있는 풀" 소품 최대 24개를 실시간으로 그려 발에 밟히면 휨(스프링 k 80, c 9).

## 10. 오너 지시 반영 — "수제 코어 + 절차적 변종"으로 수천~수만 규모

> 지시: 곤충 1,200(기본 200종 × 변종 6) / 물고기 1,200(동일) / 주민 6,000(수제 80 + 절차 생성 여행자) / 가구 60,000(기본형 ~600 × 재질 × 색). 각 항목이 "뻔한 리컬러"가 아니어야 하고, 귀여움·구별성을 **자동 QA**로 판정해야 한다.
> 2조 입장(기록): 숫자 자체는 생성기로 도달 가능. 단 "구별성"은 **층위별로 다른 기준**을 적용해야 거짓말이 안 된다 — ①기본종/기본형은 **형태가 달라야** 하고 ②변종은 **규칙화된 연출이 달라야** 하며 ③색 변형은 UI에서 **한 카드의 색상 스와치**로 묶어 "리컬러가 별개 아이템인 척"하지 않는다.

|---|---|---|---|
| L1 기본종/기본형 | 곤충 200, 물고기 200, 가구 600 | 실루엣·구조(템플릿 또는 형질 유전자 ≥3축) | 실루엣 거리 ≥ 0.18 **그리고** 특징 거리 ≥ 0.30 (§10-6) |

### 10-6. 자동 QA — "귀여운가 / 구별되는가" (`tools/qa-art.js`, art-lab에서 실행)
```js
// 툴 전용이므로 getImageData 허용. 렌더 → 32×32 알파 마스크
const silDist =(a,b)=> 0.6*(1 - iouCentered(a.mask,b.mask)) + 0.4*l1(a.hu,b.hu)/7;  // hu = Hu 모멘트 7개(log 정규화)
const featDist=(a,b)=> weightedL1(a.f, b.f, W[a.kind]);   // f = params 정규화(enum one-hot, 수치 0~1) + 팔레트 Lab 3색
function cuteScore(d){                                    // d = 렌더 측정값
  return 0.20*band(d.headBodyArea, 1.15, 1.60)            // 머리/몸 면적비
       + 0.20*band(d.eyeYRatio,    0.50, 0.62)            // 머리 상단 0 ~ 하단 1
       + 0.10*band(d.eyeGapRatio,  0.34, 0.40)
       + 0.20*band(d.roundness,    0.70, 1.00)            // 4πA/P²
       + 0.15*(1 - Math.min(1, d.sharpCorners/4))         // 곡률 임계 초과 꼭짓점(귀 끝 2개 면제)
       + 0.15*band(d.contrastL,    25, 60);               // 주체-배경 명도차
}  // band: 범위 안 1, 밖은 범위폭 대비 선형 감쇠 → 0
```
| 검사 | 대상 | 통과 기준 | 실패 처리 |
|---|---|---|---|
| L1 구별성 | 카테고리 내 기본종 전쌍(200C2 ≈ 2만 쌍, ~3s) | silDist ≥ 0.18 AND featDist ≥ 0.30 | 최근접 쌍 나란히 표시 → 수제 수정 |
| L1 형질 3축 | 템플릿 내 종 | 다른 형질 ≥ 3 | 반려 |
| L2 변종 | 종 × 6 | 규칙 적용 + ΔE ≥ 15 | 종별 대체 규칙 요구 |
| L3 색 | 가구 기본형 내 색 | 쌍별 ΔE ≥ 12, 바닥·벽지 대비 l ≥ 15 | 해당 색 마스크 제거 |
| 귀여움 | 주민·여행자·곤충·물고기 | cuteScore ≥ 0.72 (수제는 0.65 + 새봄 서명) | 테이블 제외 |
| 판독성 | 전부 | 24px 실루엣 식별 + 밤 오버레이 대비 | 반려 |
| 성능 | 생성기 | 1회 렌더 ≤ 1ms(world), ≤ 6ms(big) | 최적화 |
- 출력: `qa-report.json`(점수·최근접 이웃 3개 id) + art-lab **Nearest 뷰**(각 항목과 가장 비슷한 3개 나란히). 빌드 도구 없음 원칙에 따라 브라우저에서 수동 실행, **배포 전 필수**(UI·QA팀 체크리스트 등록).
- 사람 보정: 매주 무작위 50개 블라인드 평가(5점, 3인) 평균 < 3.8이면 W·band 범위 재조정. 자동 점수는 필요조건일 뿐 충분조건이 아님(기록).

### 10-7. 가구 60,000 = 기본형 600 × 재질 × 색
- 기본형 600을 손으로 600번 그리지 않는다: **원형(archetype) 함수 60 × 부품 모듈** 조합에서 큐레이션.
| 층 | 수량 | 내용 |
|---|---|---|
| 원형 함수 | 60 | 의자 6, 테이블 6, 소파 4, 침대 4, 수납 8, 조명 7, 장식 10, 가전 5, 벽걸이 5, 야외 5 — 구조·3면 원근·상호작용 포인트 |
| 부품 모듈 | 106 | 다리 14, 등받이 12, 상판 10, 손잡이 10, 몰딩 8, 쿠션 8, 갓 10, 받침 8, 장식 모티프 16(하트·별·구름·도토리·물고기·꽃…), 기타 10 |
| 기본형 | **600** | 원형 + 부품 3~5개 고정 조합 + 시그니처 디테일 1 (원형당 평균 10, L1 통과분만) |
| 재질 | 12 | 원목 밝음/중간/짙음, 흰도장, 파스텔도장, 비비드도장, 라탄, 은, 놋, 천, 돌, 도자 |
| 색 | 재질별 3~16 | 도장·천·도자 16색, 원목·금속·돌 톤 3 |
- 계산: 기본형당 유효 (재질, 색) 쌍 평균 100(예: 천 16 + 파스텔 16 + 비비드 16 + 흰 4 + 원목 9 + 라탄 3 … 기본형마다 허용 마스크) → 600 × 100 = **60,000 엔트리**.
- id = `form(10bit) | mat(4bit) | color(5bit)` 19bit 정수. 데이터 파일엔 기본형 600행 + 허용 마스크만(≈60KB). 60,000행 테이블은 **존재하지 않는 계산형 카탈로그**.
- 표시: 상점·도감 카드는 **기본형 600장**, 재질·색은 카드 안 스와치. 수집 목표는 "기본형 도감 600 + 기본형별 색 컬렉션 별"로 분리(기획팀 협의 안건).
- 렌더: 형태 path 함수는 재질·색과 독립 → 재질 = 채움 스타일 + 결 패턴 오버레이. 캐시 키 `furn:<id19>:<rot>:<PX>`, 집 안 동시 ≤ 80개. 세이브: 보유 = id 정수 배열, 도감 = 엔트리 비트 60,000 = 7.5KB(허용).
