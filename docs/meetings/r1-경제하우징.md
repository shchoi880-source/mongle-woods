# 1차 회의 제안서 — 시스템·경제 + 하우징·꾸미기 (합동)

- 참석: **경제팀** 민준(구현) · 서연(검토) / **하우징팀** 도윤(구현) · 하린(검토)
- 원칙: 이름·규칙 전부 오리지널. 화폐는 **"콩"**(동전 그림은 작은 콩 모양), 대출은 **"둥지 약정"**, 집 평가는 **"아늑지수"**, 시세 메커닉은 **"유행 바람"**.
- 표기: 🟢 = 베타 포함, 🗓 = 6개월 로드맵. 의견 충돌은 `[충돌]`, 결론은 `[합의]`.

## 0. 핵심 쟁점 토론 요약

| # | 쟁점 | 민준(경제·구현) | 서연(경제·검토) | 도윤(하우징·구현) | 하린(하우징·검토) | 합의 |
|---|---|---|---|---|---|---|
| A | 생물 스택 | 1개씩(크기 개체차 표현) | 같은 종 5개 스택 | — | 인벤 스트레스 줄여야 | **같은 종 5 스택**, 크기 개체차는 도감 기록에만 |
| B | 대출 이자 | 무이자·무기한 | 소액 이자로 긴장감 | — | 코지 게임에 독촉 금지 | **무이자·무기한**, 단 상환 전 다음 증축 불가 |
| C | 시세 변동 폭 | ×0.5~×3.0 | 최대 ×2.0 (인플레 위험) | — | — | **×0.8~×2.2** + 같은 날 판매 포화 감가 |
| D | 회전 | — | — | 4방향 전부 | 베타 공수 과다 | 베타: **정면/측면 2방향 + 좌우반전 = 4방향 표현** |
| E | 아늑지수 공개 | 점수 숫자 공개 | — | 숫자 공개 | 숫자는 압박, 등급만 | **등급+힌트 3줄 공개, 숫자는 설정에서 켜기** |
| F | 도구 내구도 | 있음 | 있음 | — | 귀찮음 | **있음**, 단 30% 이하 시 아이콘 깜빡임 + 수리 레시피 제공 |

`[충돌 기록]` C안: 민준은 "×3.0 대박 날이 있어야 매일 확인 동기가 생긴다"고 주장, 서연은 "월 6 시점 고가 화석×3이면 하루 수입이 목표의 4배로 튄다"는 시뮬레이션을 제시. 상한 2.2로 타협하고, 대신 **'돌풍 날'(월 2회, 한 태그만 ×2.2 고정)**을 이벤트로 남겨 민준 의도를 살림.

## 1. 아이템 데이터 모델 🟢

### 1.1 카테고리 (category)
`material`(재료) · `fruit`(과일) · `flower`(꽃) · `fish`(물고기) · `bug`(곤충) · `fossil`(화석) · `shell`(조개) · `tool`(도구) · `furniture`(가구) · `wall`(벽지) · `floor`(바닥재) · `rug`(러그) · `wallItem`(벽걸이) · `smallItem`(탁상 소품) · `clothing`(옷: 모자/상의/하의/신발 subcat) · `seed`(씨앗·묘목) · `food`(음식/소모품) · `recipe`(설계 쪽지) · `key`(퀘스트/고유, 판매 불가)

### 1.2 정적 정의 스키마 (`G.items.def[id]`)
```js
{
  id: "chair_pine_01",          // 고유 문자열 키 (세이브에는 이 키만 저장)
  cat: "furniture", sub: "chair",
  name: "소나무 의자",  desc: "앉으면 송진 냄새가 난다.",
  buy: 1200,                    // 상점 구매가 (null = 상점 판매 안 함)
  sell: 300,                    // 기본 판매가 (보통 buy의 1/4)
  stack: 1,                     // 최대 스택 (재료 30, 과일 10, 생물 5, 가구 1)
  tags: ["wood","natural","cottage","brown"], // 유행 바람·아늑지수에 사용
  colors: ["brown","cream"],    // 아늑지수 색 조화 (팔레트 12색 중)
  theme: "cottage",             // 세트 테마 1개 (없으면 null)
  season: null,                 // 생물/과일: {months:[3,4,5], hours:[6,18]} — 시간·생태팀과 공유
  rarity: 1,                    // 1~5, 상점 등장 가중치·포장 연출
  recipe: { bench:"basic", mats:{wood_soft:4, branch:2}, time:0 }, // null이면 제작 불가
  fp: { w:1, h:1, layer:"object", surface:false, sit:1, wallOnly:false }, // 가구 발자국
  variants: [ {k:"natural", name:"원목"}, {k:"white", name:"흰색", colors:["white"]} ],
  interact: "sit",              // sit | lie | toggleLight | music | open | none
  draw: "chair_basic"           // 아트B팀 절차적 드로어 함수 키 + 파라미터
}
```

### 1.3 인스턴스(세이브) 표현 — 용량 절약
- 인벤 슬롯: `[id, qty, extra]` 배열. `extra` = 도구면 남은 내구도, 가구면 변형 인덱스, 생물이면 크기(cm×10) 정수.
- 배치 가구: `[id, x, y, dir, variant, parentIdx]` (parentIdx = 탁상 소품이 올라간 가구 인덱스, 없으면 -1).
- 예상 용량: 가구 300개 × ~40B = 12KB, 인벤+창고 440슬롯 × 25B = 11KB → **하우징·경제 합계 50KB 이하** 목표.

### 1.4 베타 아이템 수 목표
재료 12 · 과일 4 · 꽃 6 · 물고기 20 · 곤충 20 · 화석 8 · 조개 5 · 도구 7 · 가구 45 · 벽지 8 · 바닥 8 · 러그 6 · 벽걸이 8 · 소품 12 · 옷 24 · 씨앗 8 · 음식 4 · 설계쪽지(=레시피 수) → **약 200종**. (생물 종 목록은 시간·생태팀 소관, 우리는 가격·스택만 정의)

## 2. 인벤토리 🟢

| 단계 | 주머니 슬롯 | 획득 | 비용 |
|---|---|---|---|
| 시작 | 15 (5×3) | 이사 직후 | — |
| 주머니 1 | 20 | 잡화점 '덧댄 주머니' | 6,000콩 🟢 |
| 주머니 2 | 30 | 잡화점 2단계 이후 | 18,000콩 🟢 |
| 주머니 3 | 40 | 월 2 이후 공방 의뢰 | 60,000콩 🗓 |

- **스택**: 재료 30 / 과일·꽃·조개 10 / 생물 5(같은 종, 크기는 최댓값만 유지) / 씨앗 20 / 가구·옷·도구 1. 자동 합치기 → 빈 슬롯 순.
- **도구 내구도**: 낡은(40회) → 튼튼한(100회) 🟢 → 반짝이는(250회, 장식 이펙트) 🗓. 30% 이하 시 아이콘 깜빡임, 0이면 부서지며 '부러진 손잡이' 재료 1개 반환(재활용 레시피). **수리**: 작업대에서 같은 종 재료 절반 비용.
- **주머니 vs 창고**: 창고(집 저장함)는 집 단계에 연동(§6). 집 안에서는 인벤 UI 오른쪽에 창고 탭이 붙어 드래그로 이동. 🗓 '어디서든 창고 열기'는 우편함 연동으로 월 3 이후 해금(편의 해금으로 장기 목표 제공).
- 정렬 버튼 1개(카테고리→가격 내림차순). 터치: 슬롯 길게 누르기 = 메뉴(버리기/들기/정보), 탭 = 선택.
- `[충돌]` 서연은 "15칸은 첫날 낚시+채집에 부족해 판매 왕복이 지루하다"고 지적. 민준은 "부족함이 첫 구매 동기"라 반박. → 첫 주머니 업그레이드 가격을 **6,000콩(약 2~3일치)**로 낮춰 합의.

## 3. 경제

### 3.1 수입원과 목표 수입 곡선 (하루 30~45분 플레이 기준)

| 시점 | 목표 콩/일 | 주 수입원 (비중) | 다음 목표(이 시점의 '살짝 모자람') |
|---|---|---|---|
| 1일차 | 800~1,200 | 과일·조개 줍기 40%, 잡어 낚시 40%, 잡초 정리 보상 20% | 이사비 상환 5,000 + 주머니 6,000 |
| 1주차 | 2,500~4,000 | 낚시 45%, 곤충 30%, 제작품 판매 15%, 주민 의뢰 10% | 오두막 약정 30,000 (≈9일) |
| 1개월 | 7,000~10,000 | 희귀 생물 40%, 화석 감정 20%, 유행 바람 판매 25%, 의뢰 15% | 2단계 집 120,000 (≈14일) |
| 6개월 | 20,000~28,000 | 고가 생물·화석 45%, 유행 바람 30%, 꽃 교배·작물 🗓 15%, 의뢰 10% | 마지막 증축 800,000 + 고급 가구 (≈30~40일) |

**목표 곡선 규칙("한 발짝 모자람")**: 각 시점의 '다음 큰 목표' 비용 ÷ 일 수입 = **7~14일** 범위가 되도록 가격 책정. 중간에 **1~3일짜리 작은 목표**(가구 1개, 주머니, 벽지)가 항상 상점에 2개 이상 존재해야 한다(상점 회전 규칙에서 보장).

누적 추정(서연 시뮬): 1주 ~15k → 1개월 ~150k → 3개월 ~900k → 6개월 ~2.7M 콩. 집 총액 약 2.2M + 시설 0.5M + 가구 지출 → 6개월 시점 **누적 지출 ≈ 누적 수입의 95~105%**가 되도록 조정.

### 3.2 지출처(Sink)
1. 둥지 약정(집 증축) — 총 지출의 ~60%
2. 시설 업그레이드: 상점(무료, 매출 조건) · 작업대 2단계 15,000 🟢 · 마을 다리/계단 각 20,000~50,000 🗓 · 박물관 별관 기부 🗓
3. 상점 가구·옷·벽지 (매일 회전으로 '오늘만' 충동 구매)
4. 제작 재료 부족분 구매(철 1개 = 400콩, 단단한 목재 = 150콩)
5. 도구 교체·수리, 씨앗
6. 🗓 외부 꾸미기(울타리·길 포장·조명), 가구 리폼(변형 바꾸기 300콩/회)

### 3.4 일일 변동 시장 — **"유행 바람"** (오리지널)
- 마을 장터 게시판(시세판)에 매일 05:00(실시간) 갱신. 시드 = `hash(saveId, yyyymmdd)` → 오프라인·재접속에도 동일 결과.
- 매일 **태그 3개**가 '바람을 탄다': 예) `빨강`, `둥근`, `물가`. 태그 풀 40개(색 12, 형태 8, 서식지 8, 재질 8, 계절 4).
  - 1번 태그 ×1.6~2.2, 2번 ×1.3~1.6, 3번 ×1.1~1.3. 여러 태그 겹치면 **곱하지 않고 최댓값 + 0.1/추가 태그**.
  - **바람 그늘**: 태그 1개는 ×0.8 (판매 회피 유도 → 창고 보관 전략).
- **포화 감가**: 같은 날 같은 아이템 판매 시 개당 −4%, 최저 ×0.6. 다음 날 05:00 회복. (낚시 노가다 1종 반복 억제)
- **바람 예보**: 날씨와 연동, 내일 1번 태그를 50% 확률로 '힌트'만 공개("내일은 뭔가 반짝이는 게 인기일 것 같아"). → 창고에 쌓았다가 파는 계획 플레이.
- **돌풍 날**: 월 2회(시드 결정), 태그 1개 ×2.2 고정 + 장터 BGM 변주(사운드팀 요청).
- 왜 '무 주식'과 다른가: 투기 상품 매수가 없고, **이미 가진 아이템의 태그**가 수요를 결정 → 도감·수집과 맞물림. 손실 위험 없음(그늘 날엔 안 팔면 됨).

```js
G.econ.market = { day:"20261123", winds:[{tag:"red",mul:1.9},{tag:"round",mul:1.4},{tag:"river",mul:1.2}],
                  shade:{tag:"metal",mul:0.8}, sold:{ "fish_carp":3 }, hint:"shiny" }
G.econ.priceOf(id, extra) // = round(def.sell * windMul * satMul)
```

### 4.2 회전 규칙
- 매일 05:00 갱신, 시드 = `hash(saveId, date, "shop")`.
- 가구 뽑기 가중치: rarity 1=50, 2=30, 3=15, 4=4, 5=1. **직전 3일 등장 아이템 제외**, 미보유 아이템 가중치 ×2.
- 슬롯 보장: 가구 중 1개는 반드시 **현재 수입 1~3일치 가격대**('작은 목표' 보장), 1개는 현재 테마 세트 중 미보유품.
- 계절 상품: 월별 4종(시간·생태팀 계절표 연동), 1개 슬롯 고정.
- 품절 표시는 당일 유지. 🗓 '주문 카탈로그'(한 번 본 아이템 재주문, 우편 다음날 배송)는 월 2 해금.

## 5. 제작(크래프팅) 🟢

- **작업대**: 기본(집 안·야외 설치 1×1) / 2단계 '다듬은 작업대' 15,000콩(철 사용 레시피 해금) / 🗓 3단계 '장인 작업대'(리폼·변형 제작).
- **레시피 획득**: ① 시작 6종 ② 상점 설계쪽지(800~3,000콩) ③ 주민 친밀도 보상 ④ 큰 나무 그루터기 흔들기 시 1일 1회 10% 확률 '쪽지' ⑤ 도감 달성 보상(곤충 10종 등). 쪽지 사용 = 영구 등록, 중복은 판매 200콩.
- **재료**: 나뭇가지 · 부드러운 목재(소나무) · 단단한 목재(참나무) · 돌 · 점토 · 철광석 · 섬유풀 · 수액 · 조개 · 꽃. 나무 1그루 하루 3회 도끼질(목재 종류는 나무 종에 따름), 바위 1일 6회 채굴(돌 70%/점토 20%/철 10%), 바위는 마을 내 3개 매일 위치 변경(월드팀 협의).

## 7. 가구 배치

### 7.1 그리드·레이어
- 실내 1칸 = 월드 타일 1개(32px 논리, 화면 DPR 스케일). 방 = `{w,h,wall:id,floor:id,cells:[]}`. 위쪽 1줄은 **벽면**(벽걸이 전용 슬롯 `w`개).
- 레이어 4개: ① `floor`(러그, 겹쳐 놓기 불가, 다른 가구 밑에 깔림) ② `object`(일반 가구, 칸 점유) ③ `surface`(탁상 소품: `fp.surface:true` 가구 위 칸마다 1개) ④ `wall`(벽걸이, 벽 칸 1~2개 폭). 🗓 ⑤ `ceiling`(천장 조명).
- 회전 `dir` 0~3. 발자국은 dir 1·3일 때 w/h 교환. 그리기: 정면/측면 드로어 + 좌우반전(합의 D).
- 깊이 정렬: object는 (y+h) 기준, surface는 부모 위 +1.

### 7.2 터치·마우스 편집 UX 🟢
1. 집 안에서 '꾸미기' 버튼 → 편집 모드(시간 흐름 유지, 플레이어 숨김, 그리드 오버레이 20% 투명).
2. 가구 **길게 누르기 350ms** → 들어올림(살짝 튀는 스케일 1.1 + 그림자). 드래그 시 손가락 **위쪽 48px 오프셋**에 고스트 표시(손가락 가림 방지), 칸 스냅. 가능 = 초록 테두리, 불가 = 빨강 + 진동 10ms.
3. 들고 있을 때 하단 바: [회전] [창고로] [변형] [취소]. PC: R 회전, Del 창고, 휠 회전.
4. 인벤/창고 트레이(하단 슬라이드)에서 드래그해 바로 배치. 필터: 카테고리·테마·색.
5. 실행취소 20단계(`G.house.undo()`), 편집 종료 시 일괄 저장.
6. 탁상 소품은 표면 가구 위로 끌면 자동 스냅, 표면 가구를 옮기면 소품이 같이 이동.

### 7.4 **아늑지수** (집 평가)
- 평가 시점: 매주 일요일 05:00 자동 + 공방에서 '오늘 평가 받기'(1일 1회). 방마다 계산 후 합산.
- 점수 규칙 (방 단위):
  1. **기본점**: 가구마다 `10 + floor(buy/200)` (최대 120). 러그·벽지·바닥 포함.
  2. **다양성**: 서로 다른 id 수 × 25. 같은 id 4개째부터 개당 −15.
  3. **테마 세트**: 같은 `theme` 3개 +300, 5개 +700, 8개 +1,200 (방마다 최고 테마 1개만).
  4. **색 조화**: 방의 색 비중 상위 2색이 **조화표**(예: 갈색+크림, 하늘+흰, 분홍+민트 등 18쌍)에 있으면 +250, 단일색 60% 이상이면 '통일감' +200.
  5. **벽지·바닥 매칭**: 둘 다 같은 테마 +200, 조화표 색 +100.
  6. **기능**: 조명 1개 이상 +100, 앉을 곳 +80, 침대(첫 방) +80, 탁상 소품 개당 +20(최대 10개).
  7. **동선**: 문에서 BFS로 모든 상호작용 가구에 접근 가능해야 함. 막힌 가구 개당 −100.
  8. **밀도**: 점유율 30~70% 구간 보너스 +150, 85% 초과 −200.
- 등급: 씨앗 0 / 새싹 2,000 / 잎사귀 6,000 / 꽃봉오리 12,000 / 꽃 22,000 / 열매 35,000 / 큰나무 55,000. 등급 상승 시 보상(한정 가구 1개 + 대문 장식 배지).
- 힌트 3줄 예: "갈색 가구가 많네요, 크림색 러그가 어울릴지도", "책장 위가 허전해요", "숲속 오두막 세트를 2개만 더 모으면…" (합의 E).

### 9.2 리스크
1. **인플레이션**: 6개월 차 고가 생물 + 바람 2.2배 → 목표 곡선 붕괴. 대응: 포화 감가, 월 단위 시뮬 스크립트(`tools/econsim.html`)로 매 업데이트 검증.

3. **localStorage 용량**: 가구 대량 배치 시. 대응: 인스턴스 배열 압축, 50KB 예산 감시 경고.
4. **모바일 성능**: 방에 가구 150개+ 드로잉. 대응: 정적 가구는 방 단위 오프스크린 캐시, 편집 시에만 개별 렌더.
5. **터치 오조작**: 작은 소품 집기 어려움. 대응: 히트박스 최소 44px, 겹칠 때 레이어 우선순위(surface>wall>object>floor) 및 탭 반복 시 순환 선택.
6. **콘텐츠 양**: 아트B가 가구 45종 절차 드로어 작성 부담. 대응: 파라미터형 드로어(의자/탁자/선반 등 12개 베이스 × 재질·색 파라미터)로 변형 생성.
7. **IP 유사성**: 대출·시세 연출이 레퍼런스와 닮지 않게, 명칭·UI·연출은 기획팀 검수 1회 필수.
