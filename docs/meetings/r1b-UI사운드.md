# 1차 회의 반론·보강안 (r1b) — UI·QA 팀 + 사운드 팀 두 번째 페어

- 작성: **한서율**(UI·QA 2번째 페어, 모바일 UX 리드 — 상위권 코지 모바일 게임 3종 출시 경험), **노은결**(사운드 2번째 페어, 오디오 디렉터)
- 대상 문서: `r1-UI사운드.md`(1번째 페어 원안), 교차 참조 `r1-아트.md`, `r1-기획.md`, `BRIEF.md`
- 오너 추가 지시(이번 라운드 전제): **동물의 숲 급 완성도, 2D, 귀여움, 6개월+ 매일 플레이**. 카탈로그 규모 —
  곤충 1,200(기본 200종 × 변이 6), 물고기 1,200(200 × 6), 주민 6,000+(상주 80 + 절차 생성 여행자), 가구 60,000(형태 600 × 재질 × 색).
- 표기: 【비판】원안의 문제 → 【수정】우리 안 / 【결정】총괄에 올리는 확정 제안 / 【이견】두 사람 의견이 갈린 부분.
- 원칙: 원안의 좋은 뼈대(세이브 이중 슬롯, verify.js, 액션 우선순위, 접근성 3종)는 **유지**. 이 문서는 "규모가 100배가 되었을 때 무너지는 곳"과 "고급스러움이 부족한 곳"을 고친다.

## 0. 요약 (먼저 읽을 결론 12개)

1. **방향: 양방향 지원(반응형).** 폰 = 세로 기본·가로 허용, PC/태블릿 = 가로 기본. 세로 고정 + PC 나무 테두리안은 폐기.
2. **해상도: 고정 논리 해상도(180×320) 폐기.** 아트안 채택 — 타일 = 논리 32u, 화면 "짧은 변"에 보이는 타일 수로 줌을 정한다(세로 폰 11타일 / 가로 폰 9.5타일 / PC 12타일).
3. 벡터 캐시 렌더이므로 **정수배 스케일 불필요**. 대신 줌 단계를 3개로 고정(캐시 키 폭발 방지), 좌표는 기기 픽셀 스냅.
4. UI는 **dp 단위 앵커 레이아웃 2프로필(P/L)**. HUD는 캔버스, 잎첩 내부 목록·검색은 **DOM + 가상 스크롤**(6만 항목, 한글 IME, 관성 스크롤 때문).
5. 잎첩은 책갈피 7개 → **"홈 화면 + 앱 12개" 구조**로 전환(책갈피는 확장 불가).
6. 도감 1,200: **종(200) 단위 카드 + 변이 6칸 미니 그리드**, 완성도는 "종 %"를 주표시, "변이 %"를 보조표시. 미발견은 3단계(??? / 실루엣 / 공개).
7. 가구 60,000: **형태(600) 단위로 탐색 → 재질·색 피커로 변형 선택.** 초성 검색·필터 칩·즐겨찾기·"최근" 탭. 분모 60,000은 화면에 절대 단독 노출 금지.
8. 여행자 6,000+: 목록에 **만난 사람만** 노출, 분모 숨김. 여행자 외형·이름·목소리는 시드에서 결정적으로 재생성 → 세이브엔 비트 + 소수 기록만.
9. 세이브: 모든 대형 컬렉션은 **비트셋 + RLE + base64**. 최악 상태(6개월 하드코어)도 ≤ 160KB/슬롯.
10. 오디오: 원안의 "진행 4종"은 6개월에 **3주 만에 질림**. → 시간대별 테마 24개(시간마다 고유 모티프) × 계절 편곡 4 × 날씨 변형 3, 생성 변주로 매일 다르게.
11. 음질: 실시간 오실레이터 직접 연주 금지 → **OfflineAudioContext로 악기 샘플 뱅크를 굽고**(아트의 캐시와 같은 철학) 재생은 BufferSource. 생성 IR 컨볼루션 리버브 + 마스터 체인.
12. QA: 대형 카탈로그 성능 테스트(필터 ≤ 30ms, 스크롤 60fps, 아이콘 LRU), 세이브 크기 회귀, 여행자 생성 결정성·금칙어 검사를 verify.js에 추가(V13~V24).

## 1. 원안(r1-UI사운드) 조목별 비판과 수정

### 1.1 화면 방향·해상도·타일 — 아트팀과의 충돌 해소 【결정】

**충돌 정리**
| 항목 | UI 원안 | 아트안 | 문제 |
|---|---|---|---|
| 타일 | 16px | 논리 32px | 16px에 2등신 40px 캐릭터·3/4뷰 높이 12px가 안 들어감 |
| 해상도 | 월드 180×320 고정 + 정수배 | 짧은 변 11타일 기준 0.5 스냅, DPR 2 캡 | 벡터를 저해상도로 그린 뒤 확대 = 아트 헌법(워블·아웃라인 AA) 무력화 |
| 스무딩 | `imageSmoothingEnabled=false` | `true`(1:1만) | 픽셀아트 전제의 설정이 벡터 스타일과 정면 충돌 |
| 방향 | 세로 고정 | 언급 없음(가로 11타일 기준식) | 아트 공식이 "가로 11타일"이라 세로 전제와는 우연히 맞음 |

【비판】원안의 180×320은 **픽셀아트용 숫자**다. 아트가 둥근 벡터로 확정된 이상, "낮은 논리 해상도 → 정수 확대"는 얻는 것 없이 둥근 볼과 반짝 눈을 계단으로 만든다. 또 정수배 고정은 갤럭시 A(360×780 CSS)에서 2배로 떨어지는데, DPR 2.625를 곱하면 실제 픽셀이 애매하게 리샘플된다.

【비판】PC를 세로 캔버스 + 나무결 테두리로 처리하면 1920×1080 모니터 면적의 **68%가 장식**이다. GitHub Pages 웹게임은 PC 첫 체험 비중이 높고, 오너가 원하는 "동숲 급"의 첫인상은 넓은 마을 풍경에서 나온다.

【결정】
| 항목 | 값 | 근거 |
|---|---|---|
| 방향 | **폰: 세로 기본, 가로 회전 허용(자동 재배치)** / **PC·태블릿: 창 비율 그대로**(가로 기본) | 한 손 플레이(세로)와 풍경 감상(가로) 둘 다 실제 사용 패턴. 레이아웃 2벌 비용 < 사용자 이탈 비용 |
| 논리 단위 | 1u = 타일의 1/32 (아트안 그대로) | 아트 캐시 키·높이 12u·캐릭터 40u 전부 이 단위 |
| 줌 기준 | **짧은 변에 보이는 타일 수 `T`** | 기기마다 다른 긴 변은 시야 확장으로 흡수(원안의 "여백 0" 취지 계승) |
| T 기본값 | 세로 폰 **11.0** / 가로 폰 **9.5** / PC(짧은 변 ≥ 700 CSS px) **12.0** / 태블릿 **13.0** | 세로 폰 360 CSS px ÷ 11 = 타일 32.7 CSS px ≈ 손가락 탭 대상 하한(오브젝트 탭 오조작 방지). 가로 폰은 높이가 좁아 9.5로 낮춰 캐릭터 크기를 세로와 비슷하게 유지 |
| 줌 단계 | 설정 "시야": **가까이(T×0.87) / 보통 / 멀리(T×1.15)** 3단 고정 | 단계가 연속이면 아트 캐시 키(PX)가 무한 증가. 3단이면 캐시 최대 3벌, 실제로는 1벌만 상주 |
| 실내 | T×0.8(=1.25배 확대, 아트안) | 방이 작아 화면이 비지 않게 |
| 하우징 편집 | 방 전체가 맞게 자동 맞춤 + 핀치 0.8~1.6배 | 제스처 중엔 캐시를 drawImage 스케일(약간 흐림 허용), 손 뗀 뒤 300ms 후 재굽기 |
| 스케일 공식 | `PX = (shortCss × min(DPR,2)) / (T × 32)` → 0.125 단위로 스냅 | 스냅해야 같은 폰에서 회전 후 재진입 시 캐시 재사용 |
| 스무딩 | `true` + 캐시는 PX 배율로 1:1 렌더, 위치 `round(x·PX)/PX` | 아트안 1.3 그대로 채택 |
| 최소 지원 | 세로 360×640 CSS, 가로 640×360 CSS | 이보다 작으면 T를 10까지 내림(시야 축소), UI는 축소 금지 |

- 회전 처리: `resize` 디바운스 150ms → 레이아웃 프로필 교체 → 월드 캐시는 PX 동일하면 유지. 대화·포획 연출 중 회전해도 진행 상태 유지(QA 항목 R1~R4).
- `manifest.webmanifest`의 `orientation`은 **지정하지 않음**(원안 `portrait` 삭제).
- 【이견】한서율은 "가로 폰에서는 HUD를 양 측면으로 몰아 월드 중앙 확보", 노은결은 "가로 폰은 양손 전제이니 조이스틱 좌/액션 우가 오히려 자연스럽다"고 동의 → 이견 없음으로 합의. 단 **하우징 편집은 세로 폰에서 상단 60%를 방, 하단 40%를 가구 서랍**으로 쓰고 "가로로 돌리면 더 넓어요" 힌트를 1회만 띄운다.

### 1.3 HUD·메뉴 — 7앱 책갈피는 규모를 못 버틴다
- 【비판】책갈피 7개 고정은 6개월 로드맵(편지함·일기·업적·스티커북·카탈로그·부탁·도장판·사진)만 더해도 15개. 책갈피 폭 48px × 15개는 세로 560px에 안 들어감.
- 【수정】잎첩 = **표지(홈 화면)에 앱 아이콘 그리드**, 앱 진입 후엔 상단 탭/뒤로. 홈은 위젯 2개(오늘의 몽글소식 요약, 오늘의 부탁 진행도) + 앱 4×3.
- 【비판】"3초 무입력 시 HUD 반투명"은 좋으나 기준이 하나뿐. 【수정】HUD 상태 3단: **풀**(대상 근처·변화 발생) / **조용**(α0.6, 3초 무입력) / **사진**(설정에서 HUD 숨김, 두 손가락 탭으로 토글).

### 1.4 가방 — 거의 유지
- 원안 합의(롱프레스 들어올림, 일괄 판매)는 업계 정답에 가깝다. 보강만:
  - 일괄 판매 시 **"도감 미등록/미기증 생물은 기본 선택 해제 + 자물쇠 아이콘"** — 1,200종 규모에선 실수로 판 희귀 변이를 되돌릴 방법이 없다.
  - 스택 상한 정책은 경제팀이지만 UI는 99까지 2자리 숫자 표시를 보장.
  - 가방 확장 후 40칸이면 세로 5×8 → 스크롤. 원안의 4행 고정 그리드는 확장 시 깨짐 → **가상 스크롤 공통 컴포넌트**(§2.5)로 통일.

### 1.5 대화창
- 원안 35자/초, 아트 30자/초 → 【결정】**기본 32자/초**, 설정 3단(느림 22 / 보통 32 / 빠름 50 / 즉시).
- 18자×3줄은 세로 기준 작가 제약으로 유지. 가로에선 같은 줄바꿈 그대로(대화창 폭만 넓어지고 좌우 여백 증가) — 줄바꿈을 기기별로 다시 하면 대사 연출(쉼표 정지 위치)이 깨진다.
- 감정 태그 → 블립 피치 +3반음만으로는 약함. §5.7 운율 규칙으로 대체.

### 1.6 Juice
- 원안 표 5행은 **너무 얇다.** 동숲 급은 "모든 행동에 반응"이 기본값. §4에 40개 카탈로그로 대체.
- 기획 1-5 "같은 일반 아이템 10회째부터 0.4초 축약"은 반드시 UI가 구현해야 함(원안 누락).

### 1.7 세이브
- 【비판】원안은 `JSON.stringify(data)` 전제. 6만 가구 보유 여부를 객체/배열로 두면 **최대 수 MB**. FNV 체크섬도 수 MB 문자열 해시는 저가폰에서 40ms+.
- 【수정】대형 컬렉션은 섹션 API에 `kind:'bitset'` 추가(§6.4). 체크섬은 직렬화된 최종 문자열 기준 유지.
- 300KB/슬롯 목표 → **160KB/슬롯 상한, 경고 120KB**로 강화(2슬롯 + premig 백업 + 사진 썸네일 여유).

### 1.8 오디오
- 【비판】진행 4종 × 16마디 루프 = 하루 1~2시간 플레이 시 같은 화성을 **수십 번** 듣는다. 파라미터(키·BPM·악기)만 바꿔도 화성 진행과 멜로디 윤곽이 같으면 귀는 "같은 곡"으로 인식한다. 6개월 매일 플레이에선 치명적.
- 【비판】"pad: 톱니 2개 디튠"·"square 음성"·"FM bell"을 실시간 오실레이터로 바로 내면 전형적인 브라우저 칩 소리. 원안 리스크 표가 이미 인정한 문제인데 대책이 한 줄뿐.
- 【수정】§5 전체.

| 여유 | — | — | 4ms(GC·브라우저) |

### 1.10 폰트 【결정 요청】
- 아트·UI 모두 "베타 시스템 폰트". 【비판】동숲 급 인상의 30%는 **둥근 글꼴**에서 온다. 시스템 폰트(맑은 고딕/애플 SD)는 업무 앱처럼 보인다.
- 【수정】베타부터 OFL 둥근 한글 폰트 1종, KS X 1001 2,350자 + 영숫자 서브셋 woff2(목표 ≤ 350KB), 서비스 워커 사전 캐시, `font-display: swap` + 캔버스 텍스트는 `document.fonts.ready` 후 HUD 재굽기. 첫 로딩 증가(약 0.3초)는 타이틀 연출 시간에 숨긴다. 외부 이미지가 아니므로 BRIEF 제약 위반 아님 — 총괄 확인 요청.

## 2. 거대 카탈로그 UX

### 2.1 공통 원칙
1. **분모 관리**: 사람이 "도달 가능"하다고 느끼는 단위로 진척을 보여준다. 1,200 → 종 200, 60,000 → 형태 600, 6,000 → 표시 안 함.
2. **2단 탐색**: 목록은 상위 단위(종·형태·주민), 변형은 상세에서. 목록 행 수가 100배 줄면 스크롤·필터·아이콘 생성 비용도 100배 준다.
3. **필터는 칩, 정렬은 1개 드롭다운, 검색은 항상 상단 고정.** 활성 필터 수를 칩 바 끝에 배지로.
4. **상태 기억**: 앱별 마지막 탭·필터·스크롤 위치를 세션 내 유지(세이브엔 저장 안 함, localStorage 편의 키 1개).
5. **새로움 표시**: 신규 획득 = 노란 점, 열람 시 소거. 점이 50개 넘으면 "모두 읽음" 버튼.

### 2.2 도감(곤충 1,200 / 물고기 1,200)
- 탭: 곤충 · 물고기 · 화석 · (로드맵: 바다생물·꽃·별자리). 각 탭 상단에 **종 완성 바**: "곤충 87 / 200종 (43%)" + 작은 글씨 "변이 214 / 1,200".
- 변이 6칸 정의(생태·아트 합의 필요, UI는 index 0~5만 가정): ①기본 ②작은 개체 ③큰 개체 ④색변이 A ⑤색변이 B ⑥반짝(희귀). ②③은 크기 기록과 연동.
- **미발견 3단계**
  | 상태 | 조건 | 표시 |
  |---|---|---|
  | 미지 | 아무 정보 없음 | 회색 "???" 카드, 번호만 |
  | 단서 | 그림자를 봤거나 콩알 꼬물 힌트, 주민 대화 언급 | **실루엣**(아트 big 캐시를 검정 α0.75로 source-in) + 출현 힌트 1줄("비 오는 밤 연못 근처") |
  | 공개 | 1회 포획 | 컬러 + 이름 + 상세 |
  - 이유: 1,200을 전부 ???로 두면 막막하고, 전부 실루엣이면 신비감이 없다. "단서" 단계가 콩알 시스템의 보상이 된다.
- **필터 칩**: 지금 출현 / 이번 달 / 이번 달까지(곧 사라짐 ⏳) / 미발견 / 미기증 / 변이 미완 / 서식지(6) / 시간대(4) / 날씨(4) / 희귀도(4) / 크기(6).
  - "곧 사라짐"은 6개월 리텐션 핵심 장치 — 월말 7일 전부터 해당 종에 ⏳ 배지.
- **정렬**: 번호(기본) / 이름 / 판매가 / 최근 획득 / 남은 출현 기간.
- **목록 셀**: 세로 4열(셀 80dp), 가로 6~8열. 셀 = 아이콘 + 번호 + 하단 변이 점 6개(채움/빈칸). 기증한 종은 우하단 작은 박물관 도장.
- **상세**: 큰 그림(아트 `mode:'big'`, 64u) + 이름·번호 + 변이 6칸 그리드(탭하면 큰 그림 교체) + 출현 캘린더(12칸 월 막대 + 24칸 시간 막대, 현재 위치 강조) + 서식지·날씨 아이콘 + 최대 크기 기록 + 판매가 + 박물관 기증 여부 + 콩알 한마디(플레이버 텍스트). 좌우 스와이프로 이전/다음 종.
- 남반구 옵션 시 캘린더 6개월 이동 표시(시간·생태 제공 함수 사용, UI는 계산 금지).

### 2.3 가구 카탈로그(60,000)
- 데이터 가정: `formId(0..599) × matId(0..M) × colorId(0..C)` → `variantId = form*100 + mat*10 + color` 같은 **산술 ID**(테이블 6만 행 저장 금지, 유효 조합만 형태별 비트마스크). 하우징·경제팀과 확정 필요.
- **카탈로그 등록** 규칙 제안: 한 번이라도 소유한 변형 = 등록(재주문 가능). 형태를 하나라도 등록하면 그 형태의 "나머지 변형은 리폼으로 만들기 가능" 표시(경제팀 결정 사항, UI는 두 상태 모두 지원).
- **진척 표시**: "가구 형태 312 / 600" 크게, "변형 1,904" 작게(분모 없음).
- **탐색 구조**
  1. 상단 검색창(항상 고정): 이름·태그·**초성**(ㅎㅂ → 화분, 흔들의자) 검색. 결과는 형태 단위.
  2. 카테고리 레일(가로 스크롤 아이콘 12개): 전체·의자·테이블·침대·수납·조명·소파·장식·가전·벽걸이·러그·바닥소품.
  3. 필터 칩: 시리즈(테마 세트, 예: 숲속·바다·레트로·꽃·계절 한정) / 재질(8 아이콘) / **색 계열 12색 원형 스와치**(빨·주·노·연두·초록·하늘·파랑·보라·분홍·갈색·흰·검정) / 크기(1×1, 2×1, 2×2, 벽) / 보유·미보유·리폼 가능 / 즐겨찾기 / 상호작용 가능(앉기·켜기·연주).
  4. 정렬: 카테고리순(기본) / 최근 획득 / 이름 / 가격 / 시리즈.
- 색 필터의 의미: 형태 단위 목록에서 "이 색 변형이 존재하는(또는 보유한) 형태"만 남기고, 셀 아이콘을 **그 색 변형으로 바꿔** 보여준다(사용자가 보는 것 = 찾는 것).
- **변형 피커**(형태 상세): 상단 큰 미리보기(정면/측면 토글, 회전 버튼) → 재질 줄(아이콘 8개 가로) → 색 스와치 줄(형태별 3~12개). 미보유 변형은 점선 테두리 + 자물쇠/리폼 아이콘. 비교 모드: 두 손가락 길게 → 2개 나란히.
- **즐겨찾기**: 하트 토글, 형태 또는 변형 단위, 상한 500개. "즐겨찾기" 탭을 카테고리 레일 맨 앞에 고정.
- **최근** 탭: 최근 얻은 30개, 최근 배치한 30개(하우징 편집 서랍과 공유).
- 하우징 편집 서랍(§3.7)은 같은 컴포넌트를 "보유 중만" 모드로 재사용 — 구현 1벌.

### 2.4 주민·여행자(6,000+)
- 탭: **마을 주민**(현재 ≤ 10) / **알고 지낸 주민**(80명 중 만난 사람) / **여행자 수첩**(만난 여행자만).
- 마을 주민: 큰 카드 가로 스와이프(초상·이름·성격·생일·좋아하는 것·친밀도 하트·오늘 기분).
- 여행자 수첩: 표시 수 "만난 여행자 143명"(분모 금지 — 6,000은 "다 못 만난다"는 좌절 신호).
  - 셀: 초상 소형 + 이름 + 종 아이콘 + 마지막 만난 날 + 별 표시(친해진 여행자).
  - 필터: 종(20) / 성격(8) / 친해짐 / 선물 받음 / 계절 / 다시 만날 수 있음(초대 편지 보낼 수 있는 대상).
  - 정렬: 최근 만남 / 이름 / 친밀도 / 처음 만난 날.
  - 검색: 이름 초성.
  - 상세: 초상(애니 idle), "처음 만난 날·장소", 주고받은 선물, 한 줄 메모(플레이어 입력 20자), [초대 편지 쓰기].
- 기술: 목록 셀 초상은 `G.art.animal.portrait(seed, PX)` 32u 캐시, **LRU 200장** 상한. 여행자 이름은 시드 생성 → 목록 표시 시점에 계산(메모이즈), 세이브에 문자열 저장 금지.

### 2.5 공통 가상 리스트 컴포넌트 `G.ui.VList`
- DOM 컨테이너(네이티브 관성 스크롤) + 행 풀(화면 행 수 + 위아래 2행). 행마다 `<canvas>` 1개 재사용, 아이콘은 아트 캐시에서 `drawImage`.
- **dataURL 금지**(아트안 `iconURL`은 가방 20칸 규모에서만 허용). 6만 규모에서 dataURL 메모는 수백 MB.
- 아이콘 생성 지연: 스크롤 속도 > 3000dp/s면 아이콘 대신 색 점(가구의 주색) 플레이스홀더, 멈추면 프레임당 4ms 예산으로 채움.
- 필터 계산: 형태 600 / 종 200 단위 `Uint16Array` 인덱스 사전 계산(색·재질·카테고리 비트마스크), 필터 1회 ≤ 5ms 목표.

## 5. 오디오 디렉션 심화 (노은결)

### 5.1 목표 사운드
- 키워드: **"나무 악기, 펠트, 따뜻한 방, 가까이서 녹음한 것 같은"**. 반대말 = 칩튠·사각파·디지털 리버브 금속성.
- 레퍼런스 성격(소리 흉내 아님): 어쿠스틱 칼림바·마림바·펠트 피아노·나일론 기타 피킹·나무 피리, 브러시 퍼커션.

### 5.2 엔진 구조: "구운 샘플 뱅크"
- 【비판】원안은 음표마다 오실레이터+필터+엔벨로프를 실시간 생성. 화음 4성 + 멜로디 + 베이스 + 퍼커션이면 초당 노드 수백 개, 저가폰 오디오 스레드 끊김 + 소리도 단조롭다.
- 【수정】부팅 후 유휴 시간에 `OfflineAudioContext(1ch, 22050Hz)`로 **악기별 샘플을 굽는다.** 재생은 `AudioBufferSourceNode` + `playbackRate` 피치 이동(±2반음 이내) + 게인 1개.
  - 악기당 **단3도 간격 샘플**(옥타브당 4개) × 2.5옥타브 = 10샘플 × 벨로시티 2층 = 20 버퍼.
  - 길이 1.2~2.5s, mono 22.05kHz float32 → 악기당 ≈ 3.5MB, 상주 악기 6종 ≈ 21MB(계절 악기는 교체 굽기). 저사양 모드: 벨로시티 1층 → 절반.
  - 굽기 시간 목표: 악기당 ≤ 120ms(오프라인 렌더는 실시간보다 빠름), 타이틀 화면 동안 핵심 3종, 나머지 백그라운드.
- 이점: 합성 레시피를 **비싸고 풍부하게**(부분음 12개, 노이즈 트랜지언트, 필터 엔벨로프) 써도 런타임 비용 0.

|---|---|
| **칼림바** | 모달 합성: 사인 부분음 비율 **1.00 / 5.40 / 11.80**(비정수 = 금속 텅 특유 색), 진폭 1 / 0.22 / 0.06, 감쇠 τ 1.4s / 0.25s / 0.08s. 어택: 4ms 노이즈 버스트 → 밴드패스 2.8kHz Q3, −18dB(엄지 닿는 소리). 기본음에 ±3센트 비브라토 4.5Hz(울림통 흔들림). 저역 120Hz 이하 컷 |
| **마림바** | 부분음 **1 / 3.93 / 9.97**(음판 튜닝 비), 진폭 1 / 0.35 / 0.08, τ 저음 0.9s → 고음 0.35s(음높이 비례 감소). 말렛 트랜지언트: 6ms 로우패스 노이즈(2kHz). 공명관 흉내: 기본음 피크 EQ +3dB Q8. 벨로시티 높을수록 3.93배 부분음 +4dB(단단한 말렛) |
| **소프트(펠트) 피아노** | `PeriodicWave` 하모닉 1~16, 진폭 1/n^1.6 + 인하모니시티 `fn = n·f0·√(1+B n²)`, B=0.0004(부분음별 사인 합으로 구움). 3현 흉내: 같은 음 3개 ±1.2/0/+0.9센트 디튠 합. 필터 엔벨로프 로우패스 5.5kHz → 900Hz(τ 0.35s), 펠트 = 해머 노이즈 −30dB + 컷오프 상한 낮춤. 2단 감쇠(빠른 τ 0.6s 70% + 느린 τ 4s 30%) = 피아노의 "프롬프트/애프터사운드" |
| **플럭(나일론 기타 느낌)** | 카플러스-스트롱을 오프라인에서 직접 샘플 연산(JS 루프로 Float32Array 생성, 노드 불필요): 지연선 길이 = SR/f0, 감쇠 0.996, 1차 로우패스 평균, 초기 노이즈를 핑크 노이즈 + 로우패스 3kHz(손가락 살)로. 픽 위치 콤 필터(지연 1/5) 1회. 바디 공명 피크 EQ 110Hz/220Hz +2dB |
| **플루트(나무 피리)** | 지속음이라 **실시간**(유일한 예외, 동시 2성 제한): 사인 + 2배음 0.12 + 3배음 0.04, 어택 80ms, 비브라토 **딜레이 250ms 후** 5.2Hz ±10센트로 페이드인. 브레스: 화이트 노이즈 → 밴드패스(중심 = 2·f0, Q 2) −24dB, 어택 시 −12dB로 부풀었다 감소. 음 연결 시 레가토 포르타멘토 40ms |
| 패드(밤) | 톱니 금지 → 삼각파 4성 각 ±7센트 + 로우패스 1.2kHz + 느린 LFO(0.08Hz)로 컷오프 ±200Hz. 미리 구운 8초 루프 |
| 베이스 | 사인 + 삼각 30% + 로우패스 600Hz, 어택 15ms(손가락 베이스), 짧은 τ 0.8s. 근음 아래 옥타브 금지(폰 스피커에서 머드) |
| 퍼커션 | 브러시(대역 노이즈 스웰 120ms), 셰이커(하이패스 노이즈 6kHz 30ms), 나무 블록(사인 900Hz τ 40ms + 클릭), 손뼉 대신 손가락 스냅 |
| 벨/셀레스타(겨울) | FM 2op(비율 3.5, 지수 감쇠 인덱스) 대신 **부분음 1 / 2.76 / 5.40 / 8.93 합산**(종 모드) — FM보다 덜 디지털 |

### 5.4 보이싱 규칙(따뜻함의 원천)
1. 반주는 **오픈 보이싱**: 근음(베이스) + 5도/10도 위로 벌림, 3도는 C3 아래 금지.
2. 화음 내부에 **add9·maj7·6** 텐션 기본(낮), 밤은 sus2·maj9, 새벽은 근음 생략 보이싱(공중에 뜬 느낌).
3. 멜로디는 최상성, 반주 최상성과 2도 충돌 시 반주 음 한 옥타브 하강.
4. 보이스 리딩: 화음 전환 시 각 성부 이동 최소(공통음 유지, 이동 ≤ 장2도 우선) — 생성 알고리즘에 비용 함수로.
5. 음역 지도: 베이스 E1~E2는 폰 스피커에서 안 들림 → 베이스는 A1~A2 + 한 옥타브 위 배음 강조(심리음향 "들리는 저음").

### 5.6 공간·마스터 체인
- **생성 IR 컨볼루션 리버브**(오프라인으로 IR 버퍼 굽기):
  - 스테레오 2채널 독립 화이트 노이즈 × 지수 감쇠 `e^(−6.9 t / RT60)`.
  - 시간에 따라 어두워지게: 블록 단위(10ms)로 1차 로우패스 계수를 8kHz → 2.5kHz로 이동(실제 방의 고역 흡수).
  - 초기 반사: 처음 80ms에 임펄스 6개(지연 7·13·19·29·41·53ms, 진폭 0.5→0.15, 좌우 교차).
  - 프리셋: **방**(RT60 0.7s, 실내·상점) / **숲**(1.6s, 낮) / **밤 언덕**(2.6s, 밤·겨울 +0.4s) / **동굴·박물관**(3.2s). 프리딜레이 15~30ms(DelayNode).
  - 컨볼버 2개만 상주(현재 + 크로스페이드 대상), 길이 = RT60 × 1.2s, 22.05kHz.
- 마스터: 버스 합 → 하이패스 45Hz → 로우셸프 +1.5dB@180Hz(따뜻함) → 하이셸프 −2dB@9kHz(디지털 쏘는 느낌 제거) → `DynamicsCompressor`(threshold −18, ratio 2.5, attack 15ms, release 250ms, 글루 용도) → 소프트클립 `WaveShaper`(tanh, 드라이브 1.2, oversample '2x') → 리미터성 컴프(−1dBFS).
- 테이프 느낌(선택, 밤만): 전체 피치 0.3Hz ±2센트 워블(BGM 버스 `playbackRate`가 아닌 각 보이스 detune 공통 LFO 값 반영).
- 스테레오: 악기 배치 고정(피아노 중앙, 칼림바 L20, 마림바 R25, 플루트 R10, 퍼커션 L35/R35). 폰 모노 스피커 대비 **모노 합산 체크**(위상 상쇄 없는지 QA).

### 5.7 24시간·계절·날씨
- **시간 테마 24개**: 원안 "진행 4 × 파라미터"를 → **시간마다 고유 모티프(2마디 동기) + 진행 8종 풀에서 2개 배정**으로. 즉 24 모티프 × A/B/C 섹션. 같은 시간대 군(새벽/낮/저녁/밤)은 악기·템포 성격 공유.
  - 정시 전환: 현재 프레이즈 끝(최대 8마디)까지 기다린 후, **정시 차임**(그 시간 모티프 첫 2마디를 칼림바 솔로로) → 새 곡. 기다림 상한 20초.
- **생성 변주**: 곡 구조 = A(모티프 원형) B(모티프 변형: 역행·확대·음정 반전 중 시드 선택) A'(장식음 추가) C(브리지, 4일에 1번만 등장 — "오늘은 이 부분이 나오네" 발견감).
- **계절 편곡 4**(같은 모티프, 다른 옷):
  | 계절 | 리드 | 반주 | 템포 | 스케일/색 |
  |---|---|---|---|---|
  | 봄 | 플루트·칼림바 | 플럭 아르페지오 | 기준 | 메이저 + add9 |
  | 여름 | 마림바 | 셰이커·플럭 스트럼 | +6% | 믹솔리디안 색, 스윙 +2% |
  | 가을 | 펠트 피아노 | 첼로풍 패드(로우패스 짙게) | −5% | 도리안 색, maj7 |
  | 겨울 | 셀레스타·벨 | 피아노 롤 + 긴 리버브 | −10% | 리디안 #4 색 |
- **날씨 변형 3**: 맑음(전 편성) / **비**(퍼커션 제거, 피아노 소프트 페달 = 컷오프 −40%, 템포 −8%, 노트 밀도 70%, 실외 BGM 로우패스 2.2kHz) / **눈**(리버브 +0.5s, 베이스 제거, 고음 벨 2성). 바람 강한 날: 플루트 비중↑, 패드 LFO 빠르게. 천둥: 천둥 순간 BGM 1.5s 덕킹 −6dB.
- **특수 테마**: 상점·박물관·집(집 = 플레이어가 놓은 "음악 상자" 가구로 교체 가능), 이벤트 8종, 등불 점등 스팅어, 생일.
- 총량(6개월 시점): 모티프 24 + 실내/이벤트 14 = 38 테마 × 계절 4 × 날씨 3 = 456 조합, 생성 변주로 매일 다름. 베타: 24 모티프 중 **12개**(2시간마다 1개, 나머지는 인접 모티프 변형) × 계절 4(현재 계절 우선 구현) × 날씨 3.

### 5.9 주민 목소리 합성
- **노드 재사용 보이스**: 주민당이 아닌 "말하는 사람 1명 = 상주 체인 1개"(오실레이터 1 + 노이즈 소스 1 + 밴드패스 F1/F2/F3 + 게인). 블립은 `setValueAtTime` 자동화로만 → 블립마다 노드 생성 0.
- 파형: 사각파 금지 → **삼각 + 톱니 20% 혼합**을 `PeriodicWave`로(배음은 있되 귀 아프지 않음), breathy = 노이즈 혼합 0~35%.
- **성격별 기본 음높이·운율**(기획 성격 8종 가정):
  | 성격(가칭) | 기본음 | 속도 | 피치 폭 | 특징 |
  |---|---|---|---|---|
  | 발랄 | 420~520Hz | 1.25 | ±5반음 | 상승 끝맺음 多 |
  | 느긋 | 220~280Hz | 0.8 | ±2반음 | 음절 길이 +30% |
  | 새침 | 360~440Hz | 1.0 | ±3반음 | 문장 끝 하강 짧게 |
  | 무뚝뚝 | 180~240Hz | 0.95 | ±1.5반음 | breathy 0.3 |
  | 다정 | 300~360Hz | 0.95 | ±3반음 | 첫 음절 슬라이드 업 |
  | 열혈 | 260~330Hz | 1.2 | ±4반음 | 강세 음절 +3dB |
  | 수줍 | 380~460Hz | 0.85 | ±2반음 | 볼륨 −3dB, 말끝 흐림(페이드) |
  | 수다 | 340~420Hz | 1.35 | ±4반음 | 쉼표 정지 −40% |
  - 종 보정: 곰·판다 −3반음, 햄스터·다람쥐 +4반음, 오리 = F2 고정 1.6kHz(꽥 색), 양 = 비브라토 7Hz ±30센트.
  - **여행자 6,000+**: `voice = f(seed)` — 성격·종 테이블 범위 안에서 결정적 생성. 저장 0바이트.
- **음절 매핑**: 초성 → 자음 트랜지언트(ㅅ·ㅆ·ㅈ·ㅊ = 고역 노이즈 15ms, ㄱ·ㅋ·ㄷ·ㅌ·ㅂ·ㅍ = 클릭 4ms, ㄴ·ㅁ·ㅇ = 비음 = F1 250Hz 강조, ㄹ = 피치 미세 굴곡), 중성 → F1/F2 표(원안 7모음군 유지), 종성 있으면 블립 길이 +20%.
- **운율(문장 단위)**: 평서문 = 전체 하강 기울기 −2반음(declination), 물음 = 마지막 2음절 +4반음 상승, 느낌표 = 첫 음절 +3반음·볼륨 +2dB, 말줄임표 = 속도 0.7 + 마지막 페이드. 감정 태그: 기쁨 +2반음·속도 1.1 / 슬픔 −3반음·속도 0.8·breathy +0.2 / 화남 피치 폭 ×0.5·볼륨 +2dB / 졸림 음절마다 −0.3반음 누적.
- 설정 "목소리 스타일": 옹알이(기본) / 짧은 블립(음절 대신 단어당 1음) / 끔.

### 5.10 오디오 성능 예산
- 동시: BGM 보이스 ≤ 16(BufferSource), 효과음 ≤ 12, 앰비언스 루프 ≤ 6 + 원샷 ≤ 4, 음성 체인 1, 컨볼버 2. 활성 노드 총 ≤ 80.
- 메인 스레드 스케줄러: 25ms 틱, 룩어헤드 120ms. 탭 백그라운드 시 suspend(원안 유지).
- 샘플 뱅크 메모리 ≤ 24MB(저사양 12MB).

### 6.2 세이브 크기 설계 (비트셋)
| 데이터 | 원시 | 저장 형식 | 6개월 하드코어 추정 |
|---|---|---|---|
| 곤충 포획(1,200) + 기증(1,200) + 단서(200) | 2,600 bit | 비트셋 | 325B → base64 434B |
| 물고기 동일 | 2,600 bit | 비트셋 | 434B |
| 가구 보유 변형(60,000) | 60,000 bit | 비트셋 + RLE(희소) | 원시 7.5KB, 1,900개 보유 시 RLE ≈ 2.5~4KB |
| 카탈로그 "본 적 있음"(60,000) | 60,000 bit | 비트셋 + RLE | ≈ 3~5KB |
| 크기 기록(2,400) | Uint16 × 획득분 | 희소 맵 `id:값` 델타 인코딩 | ≈ 2KB |
| 여행자 만남(6,000+) | 비트셋 | + 친해진 여행자 기록 ≤ 300명 × 12B | 0.8KB + 3.6KB |
| 주민 80 관계 | 80 × 40B | 고정 레코드 | 3.2KB |
| 가방·보관함(최대 1,600칸) | 칸 × (variantId 3B + 수량 1B) | 패킹 문자열 | 6.4KB |
| 집 배치(방 6 × 가구 ≤ 120) | 720 × 6B | 패킹 | 4.3KB |
| 맵 변경(RLE, 원안) | — | — | ≤ 20KB |
| 편지 보관(최대 300통) | 템플릿 ID + 변수 | | ≈ 15KB |
| 합계(+JSON 키·메타) | | | **≈ 70~110KB → 상한 160KB 안** |
- 비트셋 직렬화: `Uint8Array` → 0x00/0xFF 런을 `[마커, 길이]`로 RLE → base64. 길이 헤더 포함(카탈로그 확장 시 뒤에 0 패딩).
- 메모리 표현: 런타임은 `Uint32Array` 비트셋(`has/set/count` popcount), 도감 % 계산 O(n/32).
