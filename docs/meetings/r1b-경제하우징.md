- **⚠ 갱신(회의 중 오너 지시)**: 도감 규모가 "핸드크래프트 코어 + 절차적 변형"으로 확대됨 — 곤충 1,200 · 물고기 1,200(각 기본 200종 × 변형 6) · 주민 6,000(상주 80 + 절차적 여행자) · 가구 60,000(기본 형태 600 × 재질 × 색). **§9가 §2.5·§3의 수치를 대체/확장**한다(§3의 시리즈 32개는 '형태 600'의 큐레이션 층으로 유지).

## 1. r1경 항목별 비판과 수정안

### 1.1 수입 곡선(§3.1) — "목표치"만 있고 "상한 통제"가 없다
`[비판]` r1경의 곡선(1주 15k → 6개월 누적 2.7M)은 **평균 플레이어의 목표**다. 그런데 이 게임의 수입은 플레이 시간에 무제한 비례한다(낚시·곤충 무제한, r1기 §5-1). 하루 90분 플레이어는 같은 날짜에 2.2배를 번다. 6개월 경제에서 진짜 위험은 평균이 아니라 **상위 20% 플레이어가 3개월째에 모든 목표를 끝내는 것**이다.
- r1경 6개월 일수입 20~28k vs r1기 40~80k: 두 팀 수치가 2~3배 차이. 어느 쪽도 생물 200종의 가격대를 근거로 계산하지 않았다.
- `[수정안]` 수입은 **3개 레버로만** 오르게 한다: ① 새 종 해금(콘텐츠), ② 희귀 출현 확률 상승(도구 등급·미끼), ③ 유행 바람(상한·수요량 통제). **배율 아이템(판매가 ×N 버프) 영구 금지.**
- 6개월차 표준(40분/일) 일수입 **34,500몽**, 하드코어(90분) 약 **72,000몽**으로 확정 제안(§2 시뮬). 기획팀 40~80k는 하드코어 기준으로 재해석하면 양 팀 모두 수용 가능.

### 1.2 유행 바람(§3.4) — 콘셉트는 좋다, 숫자가 위험하다
`[비판 A: 저장-투매]` 창고 400칸 × 생물 5스택 = 2,000마리. 4개월차 귀함 물고기 평균 1,800몽 × 2.2(돌풍) = 3,960 × 2,000 = **약 790만 몽을 하루에**. 포화 감가는 "같은 아이템" 기준이라 200종을 섞으면 거의 작동하지 않는다. 6개월 설계 총 지출(약 410만)이 하루에 무너진다.
`[비판 B: 상한 붕괴]` "최댓값 + 0.1/추가 태그" → 태그 4개 아이템이 바람 3개를 모두 타면 2.2+0.2 = **2.4** (상한 2.2를 스스로 위반).
`[비판 C: 바람 그늘]` ×0.8 그늘 태그는 "안 팔면 됨"이라 의미가 없거나, 모르고 판 초보만 손해. 손해만 있는 규칙은 코지 게임에서 불쾌감만 남긴다.
`[수정안]`
1. **장터 수요량**: 바람 태그마다 하루 수요 **40개**(돌풍 날 80개). 그 태그를 가진 아이템이 팔릴 때마다 1 차감, 0이 되면 그 태그 보너스 종료. 시세판에 "빨강 ■■■■□ 32/40" 게이지 표시. → 하루 바람 보너스 최대 이득이 수치로 상한화된다(4개월차 기준 약 +6,000~9,000몽/일).
2. 최종 배율 = `min(2.2, max(태그배율들) + 0.05 × (추가 태그 수))`. 하드캡.
3. 바람 그늘 삭제 → 대신 **"고요한 태그"**: 이 태그 아이템을 주민 의뢰에 납품하면 반짝 도장 +1. 손해 대신 대안 경로를 준다.
4. 유행 바람 적용 대상은 **자연물만**(생물·화석·조개·과일·꽃·재료). 가구·옷은 제외(§1.4 차익 방지).
5. 동일 아이템 포화: r1경 −4%/개(최저 0.6)와 r1기 "20개 초과 50%"를 통합 → **같은 아이템 11개째부터 개당 −5%, 최저 ×0.5**. 10개까지는 감가 없음(초보가 모르고 손해 보지 않도록).

### 1.3 인벤토리(§2)
- `[충돌]` 시작 칸: r1경 15 vs r1기 20. `[결정]` **20칸**. 오너가 "깊이"를 원한 것이지 "불편"을 원한 게 아니다. 첫 업그레이드 동기는 칸 수가 아니라 **"주머니 무늬"(외형 8종)** 로 보강.
- 단계: 20 → 30(8,000몽, 3일차~) → 40(38,000몽, 3주차~) 🟢 → 50(120,000몽, 2개월차~) 🗓.
- 창고: r1경 최대 400칸은 OK. 단 **생물·화석은 창고에서 스택 5 → 3**으로 낮춘다(투매 완화 + 박물관·어항 사용 유도). 주머니에서는 5 유지.
- 도구 내구도 `[비판]` 40회는 낚시 기준 실시간 10~12분. 6개월 동안 매일 2~3회 교체 = 누적 400회 이상의 잡일. `[수정안]` 낡은 80 / 튼튼한 200 / 반짝이는(🗓, 3개월차 레시피) **무한 + 장식 이펙트**. 반짝 도구가 그 자체로 4~6개월차 목표가 된다(재료: 별조각·금광석).

### 1.4 가격 정의(§1.2, §3.3) — `buy÷4` 일원화는 1,000개 규모에서 깨진다
`[비판]` 가구 1,000개 중 절반은 상점에서 안 판다(레시피·선물·이벤트). `buy:null`인 아이템의 판매가가 정의되지 않는다. 또 "무료 재료 → 제작 → 판매"가 노동 대비 이득이면 낚시보다 벌목이 최적해가 되어 게임 정체성이 흔들린다.
`[수정안]` 아이템 정의에 **`val`(기준 가치)** 필드를 추가하고 모든 가격을 여기서 파생:
```js
// 단일 진실 원천. buy/sell은 계산값(데이터에 직접 쓰지 않음)
val: 1200,          // 기준 가치(몽)
src: ["shop","craft","gift","event","mail","peddler","trophy"], // 획득 경로(복수)
// sell = 상점품 floor(val*0.25) / 제작품 round(Σ재료 sell × 1.15) / 비매품(선물·이벤트) floor(val*0.2)
// buy  = 상점 단계별 val × (1.0, 1.0, 1.1, 1.2)  ← 후반 상점일수록 비싸짐(완만한 가격 인상 = 인플레 흡수)
```
- 결과: 제작 판매 차익은 최대 +15%(재료 채집 시간 고려 시 낚시보다 확실히 비효율). 상점품은 사서 되팔면 무조건 −75%.

### 1.5 집(§6) — 금액보다 **시간 게이트**가 문제
`[비판]` r1경 총 2,265k, r1기 총 1,277k. 금액 차이보다 심각한 것은 둘 다 "돈만 있으면 다음 단계"라는 점. 하드코어 플레이어(일 7만)는 r1경 기준 **약 60일에 집 완성** → 4~6개월에 할 일이 없다.
`[수정안]` 단계별 **최소 경과일(이사일 기준) AND 조건(마을 활동) AND 완납**. 표는 §2.4.

### 1.6 상점(§4) — 1,000개를 보여주기엔 진열대가 좁다
`[비판]` 단계 4 기준 가구 10칸/일. 상점 판매 대상 가구 모델 약 190종(§3.3) × 변형을 생각하면 수량 자체는 6개월에 커버되지만, **rarity 5 가중치 1/100 × 10칸 = 하루 0.1개** → 특정 고급품을 기다리다 지친다.
`[수정안]` ① 가중치 50/30/15/4/1 → **40/30/18/9/3**. ② **"찜 목록"** 3칸: 카탈로그에서 본 적 있는 아이템을 찜하면 등장 가중치 ×4. ③ 주문 카탈로그(월 2 해금)는 **배송비 10%** + 하루 주문 5개 제한 → 편의를 주되 싱크로 기능. ④ rarity 5는 상점 회전에서 빼고 **행상·특별 주문 전용**으로 이관(희소성 연출 분리).

### 1.7 아늑지수(§7.4) — 합산식의 구조적 결함
`[비판]` 직접 계산해 봤다. 8×8 방(64칸), 점유 70% ≈ 가구 30개 가정: 기본점 30×60=1,800 + 다양성 30×25=750 + 세트 1,200 + 색 450 + 벽·바닥 300 + 기능 ~460 + 밀도 150 = **약 5,100/방**. 방 8개 전부 만점이어도 41k → **최고 등급 '큰나무 55,000'은 도달 불가.** 반대로 1×1 싸구려 소품을 종류별로 깔면 다양성 점수가 선형 증가해 "잡동사니 방"이 이긴다. 그리고 텐트·오두막 단계 플레이어는 원리상 높은 등급을 받을 수 없다 → **작은 집을 좋아하는 플레이어를 처벌**한다.
`[수정안]` §3.6 아늑지수 v2 — 방마다 100점 만점, 항목별 상한, 집 등급 = 방 점수 평균.

### 1.8 레시피(§5)
- 베타 25종 → 오너 기준 **40+** 필요. 정식 300+는 §3.4.
- 그루터기 쪽지 10%/일은 OK. 단 **중복 쪽지 판매 200몽** → 쪽지를 주민에게 "선물"하면 친밀도 + 다른 쪽지 교환(중복이 사회적 자원이 되도록) 🗓.

### 1.9 저장 용량(§1.3)
- 가구 1,250 엔트리 + 옷 530 + 레시피 320 + 도감 380종 → 보유/열람 비트필드 합 약 **0.7KB**(base64 1KB). 문제 없음.
- 배치: 방 최대 9개 × 평균 60개 + 마당·마을 200개 ≈ 740개 × 40B = **30KB**. r1경 50KB 예산 안. 사진 앨범은 픽셀 저장 금지(§5.8).

### 1.10 r1기에 대한 경제 관점 비판(참고)
- r1기 §3 집 대출 총합 1,277k는 6개월 누적 수입 대비 30%에 불과 → 집 이후 싱크가 없으면 **4개월차에 잔고 100만 이상이 쌓인다.**
- r1기 §5-4 "다리 50k, 경사로 80k"는 3개월차 하루 2~3일치 → 의미 있는 목표가 아님. §4에서 재가격.
- r1기 콘텐츠표(곤충 60·가구 400·옷 250)는 오너 지시로 무효. 기획팀에 갱신 요청.

## 2. 180일 경제 시뮬레이션

### 2.1 전제
- 표준 플레이어: 하루 **40분**, 매일 접속, 도감 기증 우선(신종은 기증, 중복만 판매), 바람 수요량을 절반 정도 활용.
- 하드코어: 하루 90분, 바람 수요량 전부 활용. 수입 ≈ 표준 × 2.1.
- 계절 신종 해금으로 생물 평균 단가가 오른다(표 2.2). 화석은 하루 4개 하드리밋(r1기 §5-1), 감정 무료.
- 화폐 단위는 §6 결정안 **"몽"** 사용.

## 5. 하우징 UX 상세 (폰 우선)

### 5.1 진입·종료
1. 집 안 화면 우하단 **망치 버튼**(56px) 탭 → 0.25초 전환(화면 살짝 축소 + 그리드 페이드인 15%). PC: `E` 또는 `Tab`.
2. 편집 모드 중: 시간 흐름 유지, 플레이어·콩알은 방 구석에 앉아 관전(귀여움 연출: 콩알이 고른 가구를 따라 고개 돌림).
3. 종료: 좌상단 **✓ 완료**. 변경 사항은 종료 시 일괄 저장 + **편집 중 10액션마다 임시 저장**(별도 키 `house_edit_tmp`, 앱 강제 종료 대비 → 다음 진입 시 "이어서 꾸밀까요?").

### 5.2 화면 레이아웃
- **세로(기본)**: 상단 바 44px [✓완료][↶][↷] … [방 탭 ▢▢▢] … [📷]. 중앙 방 뷰. 하단 **트레이** 높이 28%(드래그 핸들로 12%/28%/55% 3단 스냅).
- **가로**: 트레이가 우측 30% 패널로 이동. 왼손잡이 설정 시 좌측.
- 트레이 탭: [가구][소품][벽걸이][벽·바닥][러그][야외*]. 필터 칩: 시리즈 · 색 · 희귀도 · 미배치만 · 새 아이템. 정렬: 최근 획득 / 시리즈 / 크기.
- 아이템 아이콘 64px, 우상단에 크기 표기(2×1 등)와 변형 수 점.

### 5.3 카메라
- 진입 시 **방 맞춤(fit)**: 방 전체가 상단 바와 트레이 사이 영역에 16px 여백으로 들어오게 배율 계산.
  `scale = min((viewW-32)/(cols*32), (viewH-32)/((rows+1.5)*32))` (+1.5 = 벽면 높이).
- **최소 편집 배율**: 셀이 화면에서 **36 CSS px 미만이면 fit 대신 36px로 고정**하고 패닝 허용(10×8 방 + 360px 폭 폰 → 패닝 발생).
- 제스처: 두 손가락 핀치 0.75~2.0×, 두 손가락 팬. **빈 바닥 한 손가락 드래그 = 팬**(선택 상자 아님 — 폰에서 오조작이 더 적다). 더블탭 빈 곳 = fit 복귀.
- 드래그 중 화면 가장자리 **40px 영역** 진입 시 자동 스크롤(속도 = 진입 깊이 비례, 최대 600px/s).
- 방 전환: 상단 방 탭 탭 또는 **문 셀로 가구를 끌고 0.6초 유지 → 옆 방으로 운반**(방 간 이동이 창고 경유 없이 가능).
- 2층·지하: 방 탭 그룹에 층 표시(1F/2F/B1). 계단은 고정 오브젝트.

### 5.4 선택·이동·회전 (조작 흐름)

| 동작 | 폰 | PC |
|---|---|---|
| 선택 | 가구 **탭** → 외곽선 + 위에 **미니 툴바**(이동·회전·변형·창고·정보) | 클릭 |
| 즉시 들기 | 가구 **길게 누르기 280ms**(r1경 350ms → 단축, 팬 제스처와 구분은 이동량 8px 임계) | 드래그 |
| 선택된 가구 이동 | 롱프레스 없이 바로 드래그 | 드래그 |

| 다중 선택 🗓 | 툴바 '여러 개' 토글 후 탭으로 추가, 묶음 이동 | `Shift+클릭` |

- **고스트 오프셋**: 들고 있는 가구 발자국이 **1×1 이하 또는 소품·벽걸이**면 손가락 위 1.5셀(≈54px) 위로 띄움 + 손가락 옆 **돋보기 원**(지름 96px, 2배)으로 착지 셀 확대. 2×1 이상은 오프셋 0(손가락이 가구 중심, 가구가 충분히 커서 보임).
- **스냅**: 셀 경계 120ms 이즈 + 가벼운 "톡" 효과음. 손 뗄 때 0.15초 squash & stretch(r1기 말랑 반응 규칙).
- **회전 충돌 처리**: 회전 후 발자국이 충돌하면 주변 1셀 내 유효 위치로 **자동 밀기**(가장 가까운 것). 없으면 빨강 깜빡 + 이전 방향 유지 + 진동 10ms.
- **도장 모드**: 울타리·바닥 타일·벽지처럼 반복 배치 아이템은 트레이에서 꺼내면 "연속 배치" 상태 — 탭할 때마다 1개씩 놓고, 재고가 0이 되거나 ✕ 누르면 종료.
- **실행취소/다시실행 30단계**(r1경 20 → 30). 방 전환해도 히스토리 유지, 편집 종료 시 초기화.

### 5.5 충돌 규칙 (레이어별)

| 레이어 | 점유 규칙 | 예외/특수 |
|---|---|---|
| floor(러그) | 러그끼리 겹침 금지 | **작은 러그(≤2×1)는 큰 러그 위 1단 겹침 허용** |
| object | 칸 독점 | `fp.low`(낮은 가구: 좌식 탁자·쿠션)는 앞에 1셀 여유 불필요 |
| surface | 부모의 `surfaceCells` 1칸당 소품 1개 | 2칸 소품은 같은 부모의 연속 2칸 필요. 부모 이동 시 함께 이동, 부모 창고행 시 소품은 창고로 |
| wall | 벽 행만, 벽걸이끼리 겹침 금지 | 벽 바로 앞(y=0)에 `fp.tall` 가구(책장·옷장)가 있으면 그 폭의 벽 슬롯은 **가려짐 → 배치 불가** 표시 |
| ceiling 🗓 | 2×2 영역당 천장 조명 1개 | 그리드 오버레이 대신 점선 원 표시 |
| 문 | 문 셀 + 안쪽 1셀은 **항상 비움**(배치 불가) | 계단도 동일 |
| 상호작용 면 | 의자·침대·옷장은 정면 1셀(접근 셀) 필요 | 막혀도 배치는 **허용**, 대신 ⚠ 아이콘 + 아늑지수 동선 감점 + 힌트 |

- 불가 사유를 아이콘으로 표시: 🧱 벽 / 🚪 문 길 / ⬛ 겹침 / 🙈 벽걸이 가림. 손 떼면 원위치로 튕겨 돌아감(0.2초).

### 5.6 힌트 시스템
1. **실시간 힌트 칩**: 가구를 들고 있을 때 방 카드의 꽃잎 7장 중 오르는 꽃잎이 반짝(숫자 없음). 예: 크림 러그를 갈색 방에 들면 '색 조화' 꽃잎이 깜빡.
2. **콩알 한마디**(편집 진입 시 1회 + 큰 변화 시): "책장 위가 허전해 보여!" — 힌트 풀 120줄, 아늑지수 7항목 중 최저 항목 기반.
3. **시리즈 추적**: 트레이에서 시리즈 필터 시 "솔방울 오두막 4/14 · 핵심 3/6" 진행 바.
4. **방 목적 자동 추정**: 침대 있으면 침실, 화덕 있으면 주방 → 해당 목적 가구 추천 3개(보유 중인 것 우선).
5. 첫 3회 편집은 튜토리얼 말풍선(들기·회전·창고), 이후 설정에서 다시 보기.

### 5.7 성능
- 정적 가구는 **방 단위 오프스크린 캐시**(r1경 유지). 편집 중엔 "들린 가구 + 주변 3셀 더티 영역"만 재렌더.
- 방당 가구 상한 **120개**(소품 포함), 집 전체 600개. 초과 시 배치 불가 안내(저장 용량·60fps 보호).
- 히트 테스트는 셀 맵 O(1) + 레이어 우선순위, 픽셀 판정 안 함.

### 5.8 사진 모드 🟢(기본) / 🗓(확장)
- 진입: 편집/일반 화면 상단 📷. UI 전부 숨김, 하단에 얇은 도구 줄.
- 기능: 프레임(베타 4 · 정식 24, 시리즈 연동 프레임 포함) / 필터 6(기본·따뜻·필름·흑백·파스텔·밤빛) / 캐릭터 포즈 8 · 이모트 12 / 콩알 위치 3 / 카메라 줌·팬 / 조명 미리보기(낮·노을·밤 — 연출용, 실제 시간 변경 없음) / 스티커북 스티커 최대 5장 올리기.
- 출력: 오프스크린 캔버스에 **1080×1080 또는 1080×1920**으로 2배 해상도 재렌더 → `toBlob` → 지원 시 `navigator.share({files})`, 아니면 다운로드 링크.
- **앨범은 픽셀을 저장하지 않는다**: localStorage 5MB 제약. 대신 "장면 레시피"(카메라·필터·프레임·포즈 + 당시 방 배치 스냅샷 압축) **장당 ≤2KB, 최대 30장 = 60KB** 저장 → 앨범에서 열면 재렌더. 썸네일은 열 때 생성.
- 주민 반응 🗓: 사진에 주민이 함께 찍히면 그 주민 친밀도 +소량(1일 1회).

### 5.9 야외 편집 (마당·공용지) 🗓
- 같은 편집기 재사용, 차이점: 지형 셀(물·절벽·나무)은 배치 불가, 길 포장은 도장 모드 전용, 카메라 fit 대신 **마당 영역 고정 프레임**.

## 6. 명칭 충돌 결정안

### 6.1 화폐: 기획 "방울(◎)" vs 경제 "콩" → **권고: "몽" (표기 ◎, 그림은 작은 구름 이슬방울)**

| 후보 | 장점 | 결정적 문제 |
|---|---|---|
| 방울(◎) | 세계관(이슬방울) 연결 | 한국어 '방울'의 1차 뜻이 **종·방울(bell)** → 레퍼런스 화폐(종 = Bell)의 **의미상 번역**으로 읽힌다. BRIEF 금지 조항 위반 리스크 |
| 콩 | 짧고 귀여움, 숫자 뒤에 붙기 좋음 | 기획의 동행 캐릭터 **'콩알'**과 충돌 → "콩알에게 콩 줘" 같은 문장이 혼란. 콩알 이름이 더 정체성 가치가 큼 |
| **몽** | 타이틀 '**몽**글숲'과 직결, 1음절(1,200몽), 레퍼런스 연상 없음, 몽글바람 세계관(바람이 이슬을 굳힌 '몽글 이슬') 그대로 재사용 | 단어 자체 의미가 약함 → 설정 한 줄로 보강: "몽글바람이 굳힌 이슬 알갱이, 줄여서 몽" |

- 표기: `12,500몽` / UI 아이콘 ◎(r1기 표기 유지 — 기획 안을 일부 수용). 동전 그림은 아트A: 위가 살짝 뾰족한 이슬 모양 + 하이라이트 점.
- 차선: **"이슬"**(세계관 동일, 2음절이라 숫자 뒤 리듬이 약함).

## 9. 오너 지시 갱신 대응 — 카탈로그 60,000 스케일

### 9.1 원칙: "핸드크래프트 코어"와 "절차적 변형"을 경제적으로 분리한다
- **코어**(사람이 설계): 곤충 200 · 물고기 200 · 바다 80 · 화석 100 · 가구 **형태 600** · 상주 주민 80. 출현 조건·대사·드로어가 개별 설계된다.
- **변형**(규칙으로 생성): 생물 변형 6종, 가구 재질 × 색, 절차적 여행자. 데이터는 **곱셈 규칙**으로만 존재하고 개별 테이블 행을 만들지 않는다(파일 크기·QA 부담 최소화).
- `[비판]` 60,000을 "상점에서 사는 60,000개"로 만들면 UX와 경제가 동시에 죽는다. **60,000은 '도달 가능한 조합 공간'이고, 플레이어가 6개월에 보는 진척 지표는 '형태 600'** 이다. 진행 UI는 항상 형태 단위를 1차로, 엔트리 단위는 2차(드릴다운)로 보여 준다 → "60,000 중 3%" 같은 좌절 숫자를 첫 화면에 띄우지 않는다.

### 9.2 생물 변형 6종 — 확률·가격 배율 (곤충 1,200 / 물고기 1,200)

| 변형 | 출현 확률(종 확정 후 굴림) | 판매 배율 | 유행 바람 | 판별 연출 | 조건 |
|---|---|---|---|---|---|
| 일반 | 89.0% | ×1.0 | 적용 | — | — |
| 계절색 | 6.0% | ×1.3 | 적용 | 몸 색이 계절 팔레트 | 해당 계절에만(종마다 1계절 지정) |
| 거대 | 3.0% | ×2.0 | 적용 | 그림자·크기 1.6배 이상 | 크기 상위 3% 개체 = 거대 판정 |
| 희귀 무늬 | 1.4% | ×3.0 | 미적용 | 무늬 패턴 오버레이 | 비·안개 날 ×1.5 |
| 알비노 | 0.5% | ×5.0 | 미적용 | 흰 몸·빨간 눈, 반짝이 2단계 | 밤 시간대 ×1.5 |
| 황금 | 0.1% | ×8.0 (판매가 상한 **120,000**) | 미적용 | 금빛 + 획득 연출 2초 | 반짝 도구 장착 시만 출현 |

- 기대 배율 = 0.89 + 0.078 + 0.06 + 0.042 + 0.025 + 0.008 ≈ **×1.10**. §2.2 표는 이 +10%를 낚시·곤충 열에 **이미 포함한 값으로 재해석**(변형 도입으로 표의 합계는 바뀌지 않게, 기본 종 가격 밴드를 §2.5 대비 −9% 하향 적용).
- 희귀 변형(무늬·알비노·황금)에 바람을 빼는 이유: ×5 × 2.2 = ×11 → 단발 대박이 목표 곡선을 깬다. 대신 희귀 변형은 **도감·트로피 가치**로 보상.
- **불운 보정(변형)**: 종별로 일반 30마리 연속 → 다음 개체 계절색/거대 중 하나 확정. 황금은 보정 없음(진짜 로또는 1개만).
- **판매 밴드(변형 포함, 물고기 기준)**: 흔함 일반 55~270 → 흔함 황금 440~2,160 / 전설 일반 7,300~13,600 → 전설 알비노 36,500~68,000 / 전설 황금 **120,000 상한**. 곤충도 동일 배율.
- 박물관 **기증은 기본 종 200 단위**(종당 1회, 아무 변형이나), 변형은 **변형 도감**(1,200칸)에 "기록"만 — 실물 기증 불필요(창고 압박 방지). 단 **알비노·황금은 박물관 '특별 전시대'에 선택 기증** 가능(기증 시 전시 연출 + 반짝 도장 5).

### 9.3 가구 60,000 — 형태 600 × 재질 10 × 색 10

**엔트리 공식**: `entryIdx = form × 100 + mat × 10 + color` (형태마다 정확히 100칸 예약 → 인덱스 안정). 형태가 지원하지 않는 재질은 '없음' 처리(비트는 예약만, 전체 진척 분모에서 제외). 실제 유효 엔트리 목표 **≥ 60,000**(형태별 지원 재질 수를 평균 10으로 맞추기 위해 형태 600 + 확장 예약 형태 20).

| 재질(10) | 가치 배율 | 해금 | 리메이크 재료(1회) |
|---|---|---|---|
| 소나무 | ×0.8 | 시작 | 부드러운 목재 3 |
| 참나무 | ×1.0 | 시작 | 단단한 목재 3 |
| 대나무 | ×1.0 | 1개월(대나무 숲) | 죽순대 4 |
| 등나무 | ×1.1 | 1개월 | 섬유풀 6 |
| 패브릭 | ×1.1 | 2개월(양장점) | 천 조각 3 |
| 철 | ×1.3 | 2주 | 철 2 |
| 도자 | ×1.4 | 2개월 | 점토 5 + 유약 1 |
| 유리 | ×1.6 | 3개월 | 모래 5 + 수액 2 |
| 호두나무 | ×1.8 | 4개월 | 호두 목재 3 |
| 놋 | ×2.0 | 5개월 | 금광석 1 + 철 2 |

| 색(10) | 배율 | 획득 |
|---|---|---|
| 기본·흰·검정·갈색 | ×1.0 | 시작 |
| 빨강·노랑·하늘·초록 | ×1.0 | 꽃 염료(화분 교배 꽃 2송이 = 염료 1) |
| 라벤더·민트(희귀 염료) | ×1.25 | 교배 고급 변종·이벤트 |

- **val(엔트리)** = `form.val × mat.mul × color.mul`. 판매가 규칙(§1.4)은 그대로.
- 시리즈 32개(§3.2)는 형태 600 중 384를 묶은 **큐레이션 층**. 시리즈 보너스는 **형태 기준**(재질·색 무관) → 플레이어가 재질·색을 자유롭게 바꿔도 세트가 깨지지 않는다. 색 조화(아늑지수)는 엔트리의 실제 색으로 계산 → 변형이 꾸미기 전략이 된다.

### 9.4 60,000을 얻는 경로 — 상점·인벤 UX를 지키면서

| 경로 | 무엇을 주나 | 하루 획득 엔트리(표준) | 규칙 |
|---|---|---|---|
| ① 형태 해금(상점·레시피·선물·이벤트) | 새 **형태** + 그 1개 엔트리 | 1~3 | 기존 §3.3 경로 그대로, 단위만 "형태" |
| ② 리메이크(작업대 2단계~) | 이미 가진 형태의 **다른 재질/색** | 3~10 | 비용 = 목표 val의 20% + 재질 재료 + (색은 염료 1). 원본 소모 → 결과물 1개. 1회 1.2초 |
| ③ 카탈로그 주문(월 2~) | 한 번이라도 **보유한 엔트리** 재구매 | 0~5 | 배송비 10%, 1일 5개 |
| ④ 상점 회전 | 형태 슬롯마다 **재질 1개 고정 + 색 3개 중 선택** | 1~4 | 상점 UI는 형태 단위 진열, 색은 구매 시 스와치 |
| ⑤ 여행자(절차적 주민) 교환 | 플레이어 미보유 재질·희귀 색 엔트리 | 0~2 | 여행자가 원하는 생물/가구와 1:1 교환 또는 판매 |
| ⑥ 시리즈 완성 보상 | 그 시리즈 전 형태의 **새 재질 1종 일괄 등록**(구매권) | 이벤트성 | 카탈로그에 "주문 가능"으로만 등록(실물 아님) |

- **도감 등록 기준**: 엔트리를 **한 번이라도 보유**하면 등록(되팔아도 유지). 리메이크 체인(A색 → B색 → C색)으로 원본 1개만으로 여러 엔트리 등록 가능 → 수집이 **재료 소비(싱크)** 가 된다.
- **6개월 기대치(표준)**: 형태 ~330/600(55%), 엔트리 **3,500~5,000**. 하드코어 엔트리 10,000~14,000. 60,000 완주는 **다년 목표**로 명시(2~3년차 콘텐츠의 축).
- **경제 영향**: 리메이크 비용 평균 6,000몽 × 표준 하루 3~4회 ≈ 2만 몽/일 잠재 수요 → §4 무한 싱크를 보강하는 **상시 소비처**. 하드코어 초과 수입 흡수량 충분(엔트리 1만 × 6,000 = 6,000만 > 하드코어 6개월 누적 8.7M).

**UX 방어선**
1. **상점**: 진열은 형태 단위(단계별 4~12칸 그대로). 형태 탭 → 하단 시트에 **색 스와치 1줄(10칸)** — 보유 엔트리는 체크, 미보유는 점 표시. 재질은 상점이 고정(그날의 재질 = 유행 바람 태그 연동 연출).
2. **카탈로그 화면**: 1단 = 형태 600 그리드(시리즈·용도·태그 필터, 검색) / 2단 = 선택 형태의 **재질 10 × 색 10 매트릭스**(보유 ■, 본 적 있음 ▣, 미지 □, 미지원 ✕). 60,000 리스트를 스크롤시키는 화면은 **존재하지 않는다.**
3. **인벤·창고**: 가구는 스택 1 유지하되 창고 목록은 **형태별 접힘**(예: "통나무 의자 ×7 ▸"), 펼치면 재질·색 칩. 편집 트레이(§5.2)도 동일 접힘 + 색 칩 필터.
4. **리메이크 UI**: 가구 선택 → 매트릭스에서 목표 칸 탭 → 비용 미리보기 → 확인. 미보유 칸에 ✦ 표시로 "새로 등록됨" 피드백.

### 9.5 도감 완성 보상 (스케일별 계단)

| 단위 | 조건 | 보상 |
|---|---|---|
| 생물 종 행 | 1종의 변형 6/6 | 스티커 금테 + 변형 도감 페이지 장식 |

- 보상은 전부 **비화폐 우선**(돈 보상은 인플레를 키운다). 반짝 도장 보상은 1일 상한 20.

### 9.6 주민 6,000 — 경제 관점에서만
- 상주 80명(마을 동시 최대 10~12) + **절차적 여행자**(종·색·이름·취향 시드 생성, 하루 1~3명 방문).
- 여행자의 경제 역할: ① **수요 카드**: "빨강 유리 램프를 찾아요" → 정가 ×1.5(1일 1회, 상한 3만) — 변형 수집에 이유를 준다 ② 희귀 재질·색 엔트리 판매(§9.4 ⑤) ③ 생물 변형 교환. ④ 만난 여행자 도감(6,000칸) 마일스톤 보상은 사진 프레임·스티커(화폐 없음).
- 여행자 보상의 화폐 총량은 하루 상한 3만 → 표준 일수입 표에 '의뢰·편지' 열 상향(+1,000~2,000)으로 흡수.

### 9.7 세이브 포맷 — 비트셋

| 비트셋 | 비트 수 | 바이트 | 비고 |
|---|---|---|---|
| 가구 엔트리 보유 | 62,000(형태 620 × 100) | 7,750 | 인덱스 = form×100+mat×10+color |
| 가구 형태 '본 적 있음' | 620 | 78 | 엔트리 단위 열람은 저장 안 함(형태만) |
| 생물 변형(곤충·물고기 각 1,200) | 2,400 | 300 | idx = species×6 + variant |
| 바다 80×6 · 화석 100 | 580 | 73 | 바다도 변형 6 적용 시 |
| 옷 엔트리(모델 285 × 색 10 예약) | 2,850 | 357 | |
| 레시피 320 · 여행자 6,000 | 6,320 | 790 | |
| **합계 원시** | | **≈ 9.4KB** | |

- 인코딩: `Uint8Array` → **0바이트 런-길이 압축(RLE)** → base64. 초반 세이브는 대부분 0이라 수백 바이트, 하드코어 6개월(엔트리 1.4만, 산포) 최악 ~10KB → base64 ~13KB. 전체 세이브 예산 500KB(r1기) 대비 3% 미만.
- **인덱스 안정성 규칙(필수)**: 형태·종·재질·색 목록은 **뒤에 추가만**, 삭제는 `retired:true`로 비활성. 순서 변경 금지. 데이터 파일에 `formIndex` 명시(배열 위치 의존 금지). 세이브에 `catVer` 저장, 마이그레이터가 버전별 재매핑 표 적용.
- 배치 인스턴스: `[form, mat*10+color, x, y, dir, parentIdx]` 정수 배열 → 인스턴스당 ~25B.
- 검증: 로드 시 비트셋 길이 < 현재 정의 길이면 0 패딩, 초과 비트는 무시(다운그레이드 안전).

### 9.8 베타 적용 범위 🟢
- 생물 변형 6종 **전부 베타 포함**(코드 비용 낮음: 팔레트 치환·크기 배율·오버레이) → 베타 곤충 60 × 6 = **360**, 물고기 360, 바다 20 × 6 = 120 엔트리.
- 가구: 베타 형태 122 × 재질 4(소나무·참나무·철·등나무 중 형태 지원분) × 색 8 → **약 3,500 엔트리**, 리메이크(작업대 2단계) 포함, 카탈로그 2단 매트릭스 UI 포함.
- 여행자: 하루 1명, 수요 카드만. 세이브 비트셋·RLE·`catVer` 마이그레이션은 **베타 1주차 동결 항목**.
